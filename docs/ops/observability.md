# 可观测性

观测中心按问题类型拆为五页。先选择正确页面和时间范围，再比较数据，避免把不同口径混在一起。

## 数据来源

| 数据 | 内容 | 主要页面 |
|---|---|---|
| `request_logs` | 请求、状态、耗时、流量、路由、302 和媒体语义 | 流量分析、媒体与用户、访问来源 |
| `daily_stats` | 按天聚合请求、状态、流量和延迟 | 控制台、长期趋势 |
| `security_events` | `deny`、`rate_limit` 和命中规则 | 日志与事件 |
| 播放会话注册表 | 当前活跃用户、Source 和会话 | 控制台、实时看板 |
| 文件日志 | 程序、Admin 和 Source 原始日志 | 日志与事件、服务器文件系统 |

敏感 Query 参数和 Header 会在结构化日志中脱敏，但日志仍可能包含用户、IP、媒体路径和内部地址，导出或截图前必须再次检查。

## 实时看板

用于查看当前播放状态：

- 活跃路数和活跃用户
- 并发限制状态与默认限额
- 前端每 5 秒采样、最近 5 分钟的并发趋势
- 按 Source 的活跃路数
- 当前会话明细

趋势只存在于当前打开的页面，不是持久化历史。管理员可以释放用户会话或全部会话；观察员只能查看。

## 流量分析

整合旧版“流量日志”和“302 监控”：

- 请求量、302、下行流量、平均/峰值延迟、4xx 和 5xx
- 请求与流量趋势、状态构成和延迟趋势
- **请求日志**：Proxy 或 Admin 请求明细
- **302 链路**：重定向摘要、后端/用户/IP 排行和路由 trace

页面可按 Source、流量类型、时间范围和明细条件筛选。实时追踪会周期刷新，历史排查时建议先关闭，固定时间窗口。

## 媒体与用户

包含两个视角：

- **媒体请求**：媒体请求数、302、网关代理、观测流量、逻辑播放和交付趋势。
- **使用统计**：活跃用户、完成播放、会话时长、设备、客户端和 IP 维度。

媒体标题、用户等字段可能通过异步任务补全。补全失败不会阻塞媒体转发，页面会显示失败或丢弃计数供排查。

### 302 流量边界

网关只记录发放 `302 Location` 的响应。客户端随后访问 CDN 或网盘的真实内容长度和 Range 请求不经过网关，因此：

- 302 计数可以代表直链发放次数。
- 网关“下行流量”不能代表 302 客户端实际观看流量。
- Relay 和 Emby Proxy 内容经过网关，才会进入可观测流量。

## 访问来源

用于分析客户端 IP 的地域和网络属性：

- 省份/地区、国家/地区、大区
- 家宽/IDC 等 IP 类型
- 运营商和 Top IP
- 全部请求或仅 302 直链

默认聚合路径与选择自定义时间范围后的动态日志口径可能不同，页面会提示当前使用的口径。

## 日志与事件

### 安全拦截

来自独立的 `security_events`：

- 总拦截、`deny`、`rate_limit` 和首要规则
- 按天趋势、Top 规则和 Top IP
- Source、决策、规则、状态、IP、路径和关键字筛选
- 行点击打开完整请求详情

安全事件默认按月分区并保留 90 天。

### 控制台日志

用于查看网关原始运行日志。页面缓冲区上限为 1 MB，超过后从头截断；需要更长历史时查看服务器日志文件。

## 控制台

控制台是当前状态摘要，不替代观测中心明细。主要卡片和图表使用不同时间口径：

- 今日请求和代理流量从当天 00:00 起计算。
- 302 命中率和平均延迟使用近 30 天聚合。
- 分时请求使用近 24 小时按小时聚合。
- 活跃播放来自当前会话注册表。

## 留存配置

| 配置 | 默认值 | 说明 |
|---|---:|---|
| `request_log_retention_days` | 30 天 | 请求明细保留期 |
| `stat_retention_days` | 180 天 | 聚合统计保留期 |
| `db_batch_size` | 200 | 日志批量写入条数 |
| `db_flush_interval_ms` | 1000 ms | 批量刷新间隔 |
| `security_events` | 90 天 | 固定安全事件保留期 |

PostgreSQL 请求日志按月分区。完整过期分区清理可以立即释放对应数据和索引文件；详见 [数据库维护](/ops/database-maintenance)。

## 文件日志

- `logs/error.log`
- `logs/admin-access.log`
- `logs/proxy-<source_id>-access.log`

结构化查询与文件日志应按同一时间范围交叉验证。不要因为页面暂时没有聚合数据就断定请求没有发生。
