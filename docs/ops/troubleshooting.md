# 故障排查

本页按症状组织。每个问题都按「先看哪里 → 可能原因 → 怎么处理」的顺序写。大部分问题都能在管理界面里找到线索，不需要登录服务器。

## 先收集这些信息

动手排查之前，先把下面几项记下来，之后自己对照或找人求助都用得上：

- 网关版本（管理界面顶栏右侧的版本号，点开还能看到是否有新版本）。
- 出问题的 Emby 源、媒体在 Emby 里的真实路径。
- 出问题的时间点。
- 在 <span class="ui-path">监控 › 流量分析</span> 的「请求日志」里找到那条请求，记下状态码；如果是 302，再记下命中的后端和跳转地址。
- <span class="ui-path">系统 › 系统日志</span> 里同一时间段的错误，可以用「复制脱敏记录」复制。

::: tip 先看控制台
很多问题控制台已经替你发现了。先看 <span class="ui-path">首页 › 控制台</span> 的「需要关注」和「服务状态」，见 [控制台与关注中心](/guide/dashboard)。
:::

## 管理界面打不开

**先看哪里**：网关进程或容器是否在运行，启动日志里是否有 `[AdminV2] 监听于 ...` 这一行。

```bash
docker compose ps
docker compose logs --tail=200 emby-gateway
```

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 连接被拒绝 | 端口不对：`GATEWAY_ADMIN_PORT` 或 `-admin-port` 覆盖了界面里的设置 | 以启动日志里的监听地址为准 |
| 连接被拒绝 | Docker 使用 bridge 网络但没有映射管理端口，或者防火墙、云安全组没有放行 | 映射端口或放行；host 网络模式不需要映射 |
| 返回 404 | 设置了「控制台路径前缀」 | 访问 `http://地址:端口/<前缀>/` |
| 页面能打开但接口报错 | 前面的反向代理只转发了部分路径 | 反向代理要把整个站点都转发给网关（包括 `/api`） |
| 刚升级后页面异常 | 浏览器缓存了旧页面 | 强制刷新或清除站点缓存后重新登录 |

修改「Admin Host」「Admin Port」后需要重启网关才会生效，见 [系统设置](/guide/system-settings)。

## 登录不了管理界面

- **没有登录框，直接进入了管理界面**：说明还没有设置管理员密码，任何人都能访问。请立即到 <span class="ui-path">系统 › 系统设置</span> 设置「Admin Password」。
- **提示密码错误**：管理员密码和只读密码共用一个登录框，确认输入的是哪一个。存储后端的「独立密码」不能用来登录。
- **登录后能看不能改**：用的是只读密码（Viewer Password）登录，只读账号不能修改配置。
- **过一段时间被要求重新登录**：登录有效期为 24 小时；重启网关后也需要重新登录。

## Emby 源端口不通

**先看哪里**：控制台的「服务状态」、<span class="ui-path">接入与路由 › Emby 源</span>。

| 可能原因 | 处理 |
|---|---|
| 该 Emby 源没有启用 | 启用后保存，监听会立即生效，不需要重启 |
| 两个源用了同一个端口 | 「需要关注」会提示端口冲突，给其中一个换端口 |
| Docker bridge 网络没有映射这个端口 | 每新增一个源都要在 compose 里加端口映射；使用 `network_mode: host` 可以免去这一步 |
| 防火墙或云安全组没有放行 | 放行对应端口 |

不要因为端口不通就反复保存配置，先在服务器上确认这个端口确实在监听，例如执行 `ss -lntp | grep <端口>`。

## 控制台显示「上游不可达」

网关每 30 秒检测一次 Emby 上游。显示「不可达」说明网关连不上这个源配置的 Emby 地址。

1. 在网关所在机器上测试能否访问 Emby 地址（注意容器内和宿主机的网络可能不同）。
2. 检查 Emby 源里的上游地址、路径前缀和 API Key，见 [Emby 源与路由规则](/guide/emby-sources)。
3. 检查 DNS、TLS 证书和防火墙。
4. 修正后点「服务状态」里该源右侧的刷新按钮，立即重测。

上游不可达时，网关查不到媒体的真实路径，播放请求无法生成直链；用户名、媒体名称等信息也补全不了。

## 播放没有走 302

这是最常见的问题：能播放，但视频流量都经过了网关或 Emby，没有直接从存储下载。控制台的「直链命中率」会明显偏低。

**先看哪里**：<span class="ui-path">监控 › 流量分析</span> 的「请求日志」，找到这次播放请求，看状态码和 302 相关字段。

按顺序检查：

1. **规则有没有匹配上**：到 <span class="ui-path">接入与路由 › Emby 源</span>，用「路由匹配测试」输入媒体在 Emby 里的真实路径，看命中哪条规则。注意规则匹配的是 Emby 里的**媒体文件路径**，不是浏览器地址。
2. **规则是不是被挡住了**：如果有一条匹配全部路径的兜底规则排在前面，后面的规则永远不会命中，「需要关注」会提示。把兜底规则的优先级数字调大。
3. **路径映射能不能转换**：到 <span class="ui-path">接入与路由 › 路径映射</span>，用「映射测试」验证。系统日志里出现 `路径映射未命中（回退代理）` 就是这一步失败了。
4. **资源池和后端是否存在且启用**：控制台会提示引用失效。
5. **后端能不能生成直链**：看系统日志「路由与重定向」模块有没有 `生成直链失败（跳过）`，到存储后端页面做连接测试。

::: info 为什么能播放却没有 302
网关的原则是「尽量不让播放失败」：上面任何一步失败，请求都会回退给 Emby 代理处理。所以「能播放」不代表路由配置是对的。普通播放请求没有匹配到规则时不会写系统日志，要以请求日志为准。
:::

## 收到 302，但客户端播放失败

网关已经发出了直链，问题出在客户端访问存储这一段。在请求详情里找到跳转地址（Location），检查：

- 客户端所在的网络能不能访问这个域名和端口。
- 直链是否已过期，或者签名参数不对（S3、CDN 签名有效期太短、服务器时间不准都会导致签名失败）。
- 存储或 CDN 是否支持客户端发送的 Range 分段请求。
- 本地目录、Local Agent 配置的公开地址，客户端是否真的能访问到。

## 播放被拒绝

| 返回 | 可能原因 | 在哪里看 |
|---|---|---|
| 403，提示 `license feature missing: core_redirect` | 授权失效，播放被停用 | [授权](/guide/license) |
| 429（或你配置的状态码） | 触发了「强制并发限制」，该用户同时播放的路数超过限额 | 实时播放，可以「释放该用户会话计数」 |
| 403 或其他拒绝 | 被访问规则拦截，或者该用户、IP 正处于封禁或锁定状态 | <span class="ui-path">安全 › 防护记录</span> |

通过反向代理或 CDN 访问网关时，如果没有配置真实 IP，所有用户会被看成同一个 IP，很容易被误封。请在 <span class="ui-path">安全 › 防护策略</span> 的「真实 IP」里配置可信代理，见 [防护策略](/guide/security)。

## 播放卡顿或起播慢

1. **先确认有没有走 302**：如果没有走 302，视频流量都在经过网关或 Emby，带宽瓶颈多半在这里。按上一节处理。
2. **起播慢**：看 <span class="ui-path">监控 › 流量分析</span> 的「302 链路」→「链路阶段耗时」，找出最慢的阶段。向 Emby 查询媒体路径慢，就检查网关到 Emby 的网络；生成直链慢，就检查对应后端（网盘接口响应慢、配额受限等）。
3. **播放中卡顿**：302 之后视频由存储直接提供，网关已经不参与传输。检查存储或 CDN 到客户端的带宽。
4. **使用 Relay（中转）方式的后端**：流量会经过网关，网关所在服务器的带宽决定上限。

## 某个后端一直失败

**先看哪里**：「302 链路」的「按后端成功率」，以及系统日志的「后端调用」模块（可以按后端筛选）。

- 在 <span class="ui-path">接入与路由 › 存储后端</span> 做连接测试。
- 网盘类后端检查令牌、Cookie 是否过期，接口配额是否用完。
- 系统日志出现 `Backend disabled by feature gate`：说明当前授权不包含这种后端，见 [授权](/guide/license)。

## 主后端出问题了，却没有切到备用

- 确认资源池里确实配置了备用后端，并且备用后端已启用。
- 主后端「能生成直链，但链接本身打不开」时，网关并不知道，因为 302 之后的访问不经过网关。网关是根据自己能否用主后端生成直链来决定是否切到备用的。
- 主备都失败时，请求会回退给 Emby 代理。

详见 [资源池与故障切换](/guide/routing-and-pool)。

## STRM 文件没有生成

**先看哪里**：<span class="ui-path">媒体库工具 › STRM 任务</span>，看任务卡片上的状态和上次运行的错误数，再到「运行记录」里查看详情。

- 任务必须先**保存**才能同步；状态显示「已停用」的任务不会自动运行。
- 检查后端是否支持列目录，以及源目录是否填对（可以先用「对象浏览」看一下）。
- 检查输出目录是否存在，网关进程是否有写入权限（Docker 中要把输出目录挂载出来）。
- 授权需要包含 STRM 功能。

详见 [STRM 任务](/guide/strm-guide)。

## 收不到告警通知

**先看哪里**：<span class="ui-path">安全 › 防护记录</span> 的「告警记录」。

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 告警记录里什么都没有 | 告警没有触发：告警规则页的开关没开、规则没启用，或者阈值太高 | 检查 [告警规则](/guide/security-alerts) |
| 告警记录里有，但显示投递失败 | 渠道参数错误或网络不通 | 看失败原因；到 [通知渠道](/guide/notification) 用「测试」按钮验证 |
| 通知渠道单独测试正常，告警却没送到 | 规则没有选择这个渠道，或者选中的渠道已停用 | 编辑规则，选择启用中的渠道 |

除了告警规则页的开关，<span class="ui-path">系统 › 通知渠道</span> 顶部的「通知总开关」也必须打开，否则所有通知都不会发送。近 24 小时有投递失败时，关注中心会提醒。

Telegram 在国内网络通常需要配置代理或自建 API 地址，见 [通知渠道](/guide/notification)。

## 授权异常

**先看哪里**：<span class="ui-path">系统 › 授权</span> 的状态和「最近错误」。

- 「未配置」：还没有填写授权服务地址。
- 「未激活」：输入授权码激活。
- 「宽限期」：续租一直没有成功，尽快排查网络，宽限期结束后功能会停用。
- 「时间异常」：校正服务器时间，开启 NTP 自动校时。
- 换了机器或丢失了 `data` 目录后变成「未激活」：实例 ID 变了，需要重新激活。

详见 [授权](/guide/license)。

## 数据库越来越大

- 到 <span class="ui-path">系统 › 系统设置</span> 把「请求日志保留天数」调小，保存后会立即清理一次。
- PostgreSQL 可以在「数据库维护」分区查看占用，并清理过期分区。
- SQLite 删除数据后文件不会自动变小，需要停机执行 `VACUUM`。

详见 [数据库维护](/ops/database-maintenance)。

## 监控数据和实际情况对不上

- 下行流量远小于实际观看量：正常，302 之后的下载流量不经过网关。
- 实时播放没有数据：需要在防护策略里打开「统计播放会话」。
- 刚发生的请求没有用户名：用户和媒体信息是异步补全的，稍等再看。
- 两个页面的数字不一致：确认选的是同一个 Emby 源、时间范围和请求范围。

详见 [播放与流量监控](/ops/observability)。

## 升级后异常

1. 确认镜像标签或二进制版本。
2. 查看启动日志里有没有数据库迁移、配置解密或授权相关的错误。
3. 如果设置过配置加密密钥 `GATEWAY_CFG_ENC_KEY`，升级后必须保持一致，否则配置无法解密。
4. 依次检查：管理界面能打开、Emby 源端口在监听、一次真实播放能走 302。
5. 需要回滚时，要同时考虑数据库结构是否兼容，升级前先备份数据目录或数据库。

升级步骤见 [部署与升级](/guide/deployment)。

## 求助时请提供

- 网关版本和部署方式（Docker 或二进制、SQLite 或 PostgreSQL）。
- 出问题的时间、Emby 源、请求状态码。
- 系统日志里相关的脱敏记录（用「复制脱敏记录」）。

请不要直接发送完整的数据库文件或原始配置，里面有密码和各类凭据。
