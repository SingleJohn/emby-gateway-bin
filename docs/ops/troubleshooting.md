# 故障排查

排障的目标不是先“重启试试”，而是确认请求停在了哪一层：管理端、Source、上游 Emby、路由映射、后端直链，还是客户端跳转后的存储访问。

## 先收集这些信息

记录问题发生时间和以下上下文：

- 当前网关版本，以及正式 Release 还是 `nightly`
- Source 名称、监听端口和上游健康状态
- 媒体对应的真实路径
- 请求状态码，是否收到 `302 Location`
- 命中的路由、路径映射、资源池和后端
- 「流量分析」请求详情和「日志与事件」同一时间段的错误

分享日志或截图前，必须遮挡 API Key、Token、Cookie、签名参数、完整用户/IP 和媒体路径。

## 管理后台打不开

### 连接被拒绝

依次检查：

1. 进程或容器是否仍在运行。
2. `GATEWAY_ADMIN_HOST` 是否监听在可访问地址。
3. 实际管理端口是否被 `GATEWAY_ADMIN_PORT` 或 `-admin-port` 覆盖。
4. Docker、主机防火墙和云安全组是否放行同一端口。
5. 配置了控制台路径前缀时，URL 是否包含该前缀。

Docker 常用只读检查：

```bash
docker compose ps
docker compose logs --tail=200 emby-gateway
```

### 页面能打开但 API 报错

- 查看浏览器页面提示和 `logs/admin-access.log`。
- 确认反向代理同时转发 `/ui/` 和 `/api/`。
- 若刚升级，确认内嵌 WebUI 与后端二进制来自同一构建。
- 清理浏览器站点缓存后重新登录；不要直接删除数据库。

## 登录失败

后台登录接口支持两类身份：

- 管理员密码：完整管理权限。
- 观察员密码：配置脱敏且只读。

后端独立密码只能由已经登录后台的用户在后端页面进行会话级解锁，不能直接登录后台。

如果管理员密码无法登录：

1. 确认输入的是管理员密码，不是观察员或后端密码。
2. 检查是否访问了正确的部署实例。
3. 查看 Admin 日志中的认证失败信息。
4. 恢复密码应通过已验证的数据库备份或受控运维流程处理，不要在未备份时修改或重建数据库。

## Source 端口不可访问

Source 配置保存后会热更新监听器，但外部网络配置不会自动变化。

检查：

1. Source 已启用，监听地址和端口没有与其他 Source 冲突。
2. Docker bridge 模式已显式映射该端口；host 模式无需容器端口映射。
3. 主机防火墙和云安全组已放行。
4. 控制台「服务状态」没有显示监听或上游异常。

不要因为端口不可达就反复保存配置；先确认操作系统层是否真的存在监听。

## 上游 Emby 异常

控制台显示 Emby 上游异常时：

1. 从网关所在网络测试上游地址是否可达。
2. 检查 `host`、`base_path` 和 API Key。
3. 确认反向代理没有改写 Emby API 路径。
4. 检查 DNS、TLS 证书和网络超时。

上游健康异常不一定影响已经能生成直链的所有请求，但会影响用户和媒体信息补全，也可能影响代理回退。

## 播放没有返回 302

在「观测中心 → 流量分析」定位该请求，然后按顺序检查：

1. 请求是否属于支持拦截的播放路径。
2. 是否成功解析出 Emby 真实媒体路径。
3. 是否命中预期路由；路由匹配的是真实路径，不是浏览器 URL。
4. 强制映射开启时，路径映射是否成功。
5. 路由引用的资源池和后端是否仍存在且已启用。
6. 主后端和备后端是否能为 object key 生成直链。

路由一旦命中，失败后不会继续尝试下一条路由。主备均失败时会回退 Emby 代理，因此“可以播放但没有 302”不代表路由成功。

## 收到 302 但客户端播放失败

这时网关已经完成直链发放，重点检查 `Location` 指向的目标：

- 客户端是否能访问目标域名和端口。
- 临时 URL 是否已过期或签名参数不匹配。
- CDN、对象存储或网盘是否支持客户端发送的 Range 请求。
- 本地/Local Agent 的公开地址是否真能从客户端网络访问。
- 123 拼接直链的 Base URL、UID 隐藏和路径映射是否一致。

不要只看网关下行流量判断 302 播放质量。客户端跳转后的真实字节通常不经过网关。

## 后端故障切换未发生

资源池只有一个主后端和一个可选备后端。确认：

1. 备后端已经保存到同一个资源池。
2. 两个后端都能接受映射后的同一 object key。
3. 主后端确实在“生成直链”阶段返回错误；客户端拿到 302 后的访问失败不会回到网关触发备切换。

故障切换不是持续健康检查，也不会在客户端访问目标 URL 失败后重新选择后端。

## 115 后端问题

### 115 Open

- 检查 Access Token、Refresh Token 和根目录 ID。
- 确认排序、分页和缓存配置没有造成目录定位偏差。
- `302 重定向` 与 `Relay` 是不同交付方式，排障时先确认当前模式。

### 115 Cookie

- Cookie 不保存在普通配置快照中，确认凭据状态页面没有报错。
- Cookie 失效时重新更新凭据，不要把完整 Cookie 写入日志或问题单。

### 115 分流聚合

- 确认主盘后端存在且类型为 `115_open` 或 `115_cookie`。
- 检查附盘是否启用、凭据来源是否可用、根目录和镜像目录是否一致。
- 启用“关闭主盘回退”后，附盘全部失败会直接失败，这是预期行为。
- 用户亲和或单盘策略需要可靠的 Emby 用户识别；用户信息缺失时先查媒体观测补全状态。

## STRM 任务失败

1. 在「STRM 任务 → 最近任务」打开运行详情。
2. 根据操作过滤查看扫描、写入、元数据和删除错误。
3. 检查后端是否支持目录枚举。
4. 检查媒体目录、链接目录和网关进程的文件权限。
5. Base URL 留空时生成相对媒体路径；确认这是客户端预期行为。
6. 元数据下载会额外访问上游并写本地文件，需检查网络、限流和磁盘权限。

“删除失效文件”会删除源端本轮已不存在的本地 STRM/元数据文件。首次启用前先确认输出目录没有混放人工维护文件。

## 并发播放限制问题

- 「统计播放会话」只记录会话，不会拦截。
- 「强制并发限制」开启后才按默认限额和用户独立限额拒绝新播放。
- 会话依赖用户识别和空闲超时；识别不完整时先检查 Source API Key 和用户补全日志。
- 管理员可在「实时看板」释放会话；该操作会改变运行状态，排障前先记录现场。

## 登录失败防护误封

核对生效 Source、登录路径、失败状态码、统计窗口和封禁时长。作用范围可按 IP 或 Source + IP 统计，反向代理部署还必须正确配置真实 IP 识别，否则多个用户可能被归为同一代理 IP。

## 观测数据与实际流量不一致

常见原因：

- 302 只记录跳转，不记录客户端随后访问存储的真实流量。
- 媒体和用户信息通过异步补全，刚发生的请求可能暂时缺字段。
- 按小时和按天统计使用网关配置的时区口径。
- 页面时间范围、Source、Proxy/302 模式不同会产生不同分母。
- 实时看板的趋势由前端每 5 秒采样，仅保留当前页面最近 5 分钟。

## 请求日志占用过大

生产 PostgreSQL 可在「系统 → 网关配置 → 数据库维护」查看总占用、分区和过期预览。

- 清理完整过期月分区能立即释放对应数据和索引文件。
- 清理过期日志或清空访问日志都会保留 `daily_stats`。
- 当前月份中刚超过保留天数的数据可能要等到整个分区过期后才被删除。
- 清理是不可恢复操作，必须先查看预览和数据库备份。

不要把普通 `DELETE` 后的逻辑空闲空间误认为操作系统磁盘已经回收。详见 [数据库维护](/ops/database-maintenance)。

## 升级后异常

1. 确认版本号和镜像标签；`nightly` 会滚动覆盖。
2. 查看启动日志中的数据库迁移、配置解密和许可证错误。
3. 确认 `GATEWAY_CFG_ENC_KEY` 与加密配置时一致。
4. 检查 WebUI 页面、Source 监听和一次真实播放链路。
5. 需要回滚时，同时评估数据库结构兼容性，不要只替换二进制。

## 日志位置

| 文件或页面 | 适合排查 |
|---|---|
| `logs/error.log` | 启动、后端、任务和运行时错误 |
| `logs/admin-access.log` | 登录、Admin API 和配置请求 |
| `logs/proxy-<source_id>-access.log` | 指定 Source 请求链路 |
| 流量分析 | 请求、302、路由和重定向详情 |
| 日志与事件 | 安全拦截及控制台原始日志 |
| STRM 最近任务 | 扫描、写入、删除和元数据事件 |

如果仍无法定位，请提供最小、已脱敏的时间窗口、Source、状态码、路由/后端结果和对应错误日志，不要上传完整数据库或原始配置。
