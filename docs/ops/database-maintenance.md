# 数据库维护

网关的配置、请求日志、统计、安全事件和告警记录都存在数据库里，其中请求日志增长最快。本页说明网关会自动清理哪些数据、各保留多久，PostgreSQL 下怎样在管理界面手动清理请求日志，以及 SQLite 有什么不同。

## 自动清理

网关在这些时候运行清理任务：启动时一次，之后每 30 分钟一次，以及每次保存配置后立即一次。各类数据的保留时间：

| 数据 | 保留时间 | 在哪里修改 |
|---|---|---|
| 请求日志（流量分析的请求明细） | 默认 30 天 | 系统设置 › 全局设置 ›「请求日志保留天数」 |
| 每日统计（按天、按源的聚合数据） | 默认 180 天 | 系统设置 › 全局设置 ›「统计保留天数」 |
| 播放记录 | 同统计保留天数 | 同上 |
| 媒体访问统计 | 同统计保留天数 | 同上 |
| 安全事件（拦截记录） | 固定 90 天 | 不可修改 |
| 告警记录 | 固定 90 天 | 不可修改 |
| 请求的用户与媒体补全缓存 | 1 天 | 不可修改 |

::: tip 缩短保留天数是控制数据库大小最直接的办法
如果数据库增长太快，优先把「请求日志保留天数」调小。保存后会立即触发一次清理。按天的趋势图依赖每日统计，所以清理请求日志不影响控制台和流量分析「概览」里的趋势；受影响的是更早的请求明细，以及基于请求明细计算的分析，例如 302 链路。
:::

## PostgreSQL 与 SQLite 的区别

两种数据库自动清理的方式不同，这会影响磁盘空间是否真的被释放：

| | PostgreSQL | SQLite |
|---|---|---|
| 请求日志的存放方式 | 按天分区 | 一张表 |
| 过期请求日志怎么清理 | 整个删除过期分区 | 删除过期的行 |
| 安全事件怎么清理 | 按月分区，整个删除过期分区 | 删除过期的行 |
| 清理后磁盘空间 | 删除分区会立即释放对应的数据和索引空间 | 数据库文件不会变小，空出来的空间留给之后的新数据复用 |
| 管理界面手动清理 | 支持 | 不支持 |

所以请求量大、需要长期运行的部署建议使用 PostgreSQL，配置方法见 [部署与升级](/guide/deployment)。

### 只删除整个过期分区

PostgreSQL 下，只有**整个分区都早于保留期**时，这个分区才会被删除。保留期的分界点可能落在某个分区中间，这个分区里刚过期的那一部分记录会暂时保留，等整个分区都过期后再删除。这是为了不误删仍在保留期内的数据。

## 在管理界面手动清理（PostgreSQL）

位置：<span class="ui-path">系统 › 系统设置</span>，滚动到「数据库维护」分区。只有管理员能看到这个分区；使用 SQLite 时打开会提示需要 PostgreSQL。

### 能看到什么

- **占用概况**：数据库总占用、访问日志合计、日志数据、日志索引、访问日志预估行数、每日统计的大小。
- **保留情况**：当前请求日志保留天数，以及已经完整过期、可以释放的空间。
- **分区明细**：每个请求日志分区的数据、索引、合计大小和预估行数。

### 两种清理方式

| 按钮 | 做什么 | 需要输入的确认文字 |
|---|---|---|
| 清理过期分区 | 删除已经完整超过保留天数的请求日志分区 | `清理过期日志` |
| 清空访问日志 | 删除**全部**请求日志 | `清空访问日志` |

两种方式都**只动请求日志**，每日统计（`daily_stats`）、播放记录、安全事件都不受影响，所以控制台和趋势图照常可用。

### 操作步骤

1. 先确认 PostgreSQL 有可用的备份。清理不可恢复。
2. 在「数据库维护」分区查看总占用和分区明细。
3. 点「清理过期分区」或「清空访问日志」，弹窗里会显示预计释放的空间、涉及的日志行数和分区数量。
4. 核对无误后，在输入框里输入弹窗提示的确认文字，点「确认执行」。
5. 执行完成后，点分区右上角的刷新按钮，确认占用已经下降。

::: warning 同一时间只能执行一个维护操作
手动清理和自动清理共用一把锁：手动清理执行时，自动清理会跳过这一轮；如果已经有维护任务在执行，再次提交会提示「database maintenance is already running」，等它完成后再操作即可。
:::

## SQLite 怎样缩小数据库文件

SQLite 删除数据后文件不会自动变小。确实需要回收磁盘空间时，可以在停机状态下手动执行 `VACUUM`：

1. 停止网关。
2. 备份数据库文件。默认位置是网关工作目录下的 `data/gateway.db`，Docker 中是 `/app/data/gateway.db`；同目录下的 `gateway.db-wal`、`gateway.db-shm` 一起备份。
3. 用 SQLite 命令行工具执行：

   ```bash
   sqlite3 data/gateway.db "VACUUM;"
   ```

4. 启动网关，确认管理界面和播放都正常。

`VACUUM` 期间需要额外留出与数据库文件大小相当的磁盘空间。

## 不要做的事

- 不要在没有备份的情况下手动 `DROP` 或清空配置表、统计表。
- 不要为了缩小数据库去删除每日统计，除非确实不再需要历史趋势。
- 不要在不了解影响的情况下开启 `GATEWAY_DB_ALLOW_DESTRUCTIVE_MIGRATIONS`，它允许数据库迁移执行破坏性的结构变更。参见 [启动参数与环境变量](/reference/cli-env)。
