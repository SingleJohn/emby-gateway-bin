# 路径映射

路径映射把媒体在 Emby 里的路径（例如 `/mnt/media/movies/阿凡达.mkv`）改写成它在存储里的路径（例如 `movies/阿凡达.mkv`），网关再拿这个路径去存储后端生成直链。

Emby 读取媒体用的目录和存储里的目录结构几乎不会完全一样，所以每条路由规则都要引用一个映射集。配置路由前，或播放时日志提示"路径映射未命中"时，看这一页。

## 规则集与映射条目

<span class="ui-path">接入与路由 › 路径映射</span>

一个**规则集**（配置里叫 Path Rule Set，路由规则里显示为「映射集」）包含若干条映射。每条映射是"Emby 中的前缀 → 存储中的前缀"。规则集本身不决定用哪个存储，由引用它的路由规则和资源池决定。

| 界面 | 配置字段 | 说明 |
|---|---|---|
| 规则集名称 | `path_rule_sets[].name` | 界面显示用 |
| （名称下方的 ID） | `path_rule_sets[].id` | 自动生成，路由规则通过它引用 |
| 「Emby 中的路径前缀」 | `mappings[].from` | 要被替换掉的前缀 |
| 「存储中的路径前缀」 | `mappings[].to` | 替换成的前缀，可以留空 |

每个规则集卡片会显示「被 N 条路由使用」或「尚未被任何路由使用」，删除前先看一眼。

## 新建规则集

1. 点击右上角「新建规则集」，新卡片里已带一条空映射。
2. 填写规则集名称，例如"电影与剧集"。
3. 在映射行左侧填 Emby 中的路径前缀，右侧填存储中的路径前缀。需要更多条目时点「添加映射」。
4. 在卡片底部的「映射测试」里粘贴一个真实路径，确认结果正确。
5. 点击底部的「保存」，立即生效。
6. 到 [Emby 源](/guide/emby-sources#路由规则) 的路由规则里，在「映射集」下拉框选中它。

## 匹配规则

网关处理一个路径时按以下步骤进行：

1. **归一化**：反斜杠 `\` 换成 `/`，去掉多余的 `/`、`.`、`..`。如果路径是 `http://` 或 `https://` 开头的地址，只取路径部分并解码。映射条目的两侧也做同样处理，所以末尾带不带 `/` 都一样。
2. **按顺序匹配**：从第一条映射开始，找到第一条"Emby 中的路径前缀"能匹配上的条目就停止。「Emby 中的路径前缀」为空的条目会被跳过。
3. **按目录层级判断前缀**：`/mnt/media` 能匹配 `/mnt/media/a.mkv`，**不能**匹配 `/mnt/media2/a.mkv`。区分大小写。
4. **替换**：把匹配到的前缀换成「存储中的路径前缀」，剩余部分原样接在后面。「存储中的路径前缀」留空或填 `/`，效果是直接去掉前缀。
5. **得到存储路径**：结果去掉开头的 `/`，就是交给后端的路径（文档里也叫 object key）。所以 `to` 写 `/movies` 和 `movies` 效果相同。

如果替换后什么都不剩（例如把整个文件路径映射成 `/`），映射视为失败。

### 多条映射的顺序

网关**按列表顺序取第一条命中的映射**，不会自动挑最长的前缀。更具体的前缀必须排在更宽泛的前缀上面：

| 顺序 | Emby 中的路径前缀 | 存储中的路径前缀 |
|---|---|---|
| 1 | `/mnt/media/电影/4K` | `uhd` |
| 2 | `/mnt/media/电影` | `movies` |

反过来排，第 1 条 `/mnt/media/电影` 会先把 4K 目录也吃掉，第 2 条永远用不上。

::: tip 调整顺序
映射条目目前没有上移、下移按钮。要调整顺序，删掉排在前面的条目，再用「添加映射」在末尾重新添加。
:::

### 映射没匹配上时

是否继续由路由规则的「强制映射」开关决定，详见 [强制映射](/guide/emby-sources#强制映射)：

- 「强制映射」：映射失败，这次播放回退给 Emby 推流；
- 「可选映射」：不改写，直接用原路径（去掉开头的 `/`）继续；
- 规则集里一条映射都没有时，两种设置都按原路径继续。

注意新建规则集时自带的那一条空映射：没填就保存，它也算一条"有条目"，配合「强制映射」会让所有路径都映射失败。不用的空行请删掉。

## 例子

### 替换前缀

| Emby 中的路径 | 映射 | 存储路径 |
|---|---|---|
| `/mnt/media/movies/阿凡达.mkv` | `/mnt/media/movies` → `/movies` | `movies/阿凡达.mkv` |
| `/mnt/media/tv/庆余年/S01E01.mkv` | `/mnt/media/tv` → `剧集` | `剧集/庆余年/S01E01.mkv` |

### 只去掉前缀

存储里的目录结构和 Emby 挂载点下面完全一致时，「存储中的路径前缀」留空即可：

| Emby 中的路径 | 映射 | 存储路径 |
|---|---|---|
| `/data/media/movies/阿凡达.mkv` | `/data/media` → （留空） | `movies/阿凡达.mkv` |

### Windows 路径

Emby 跑在 Windows 上时，路径形如 `D:\Media\电影\阿凡达.mkv`。归一化后变成 `D:/Media/电影/阿凡达.mkv`，映射左侧写 `D:\Media` 或 `D:/Media` 都可以：

| Emby 中的路径 | 映射 | 存储路径 |
|---|---|---|
| `D:\Media\电影\阿凡达.mkv` | `D:/Media` → （留空） | `电影/阿凡达.mkv` |

### 存储路径怎么用

得到的存储路径交给资源池里的后端，不同后端的理解不同：S3 是桶里的对象 Key（会再加上「Key Prefix」），CDN 是 URL 路径，网盘是相对根目录的路径，本地存储是相对「Base Dir」的路径。同一个资源池的主用、备用后端会收到同一个存储路径，两边的目录结构要一致。各类型细节见 [后端总览](/guide/backend-configuration)。

## 映射测试

每个规则集卡片底部都有「映射测试」，提示文字是「按列表顺序取第一条命中的映射」。

1. 从 Emby 媒体信息里复制一个文件路径；
2. 粘贴到输入框；
3. 看结果：
   - 命中时显示「命中第 N 条 →」和改写后的存储路径，对应的映射行会高亮；
   - 没命中时显示「没有命中任何映射，按原路径」和原路径。

测试按当前编辑中的内容计算，不需要先保存。

::: warning 没命中时的实际效果
测试结果里写着"路由开启「强制映射」时会直接失败"。这里的失败指不生成直链，播放本身会回退给 Emby 推流，并不会报错中断。
:::

拿到存储路径后，可以到 <span class="ui-path">媒体库工具 › 对象浏览</span> 里打开对应后端，确认这个路径下真的有文件（支持哪些后端见 [对象浏览](/guide/file-browser)）。

## 常见问题

**映射测试命中了，播放还是没走 302。**
映射只是中间一步。确认路由规则能命中（[匹配测试](/guide/emby-sources#匹配测试)），并且规则的「映射集」选的正是这个规则集；再确认资源池里的后端能用这个存储路径找到文件。

**删除规则集后播放变慢了。**
引用它的路由规则找不到映射集，播放全部回退给 Emby。删除前看卡片上的「被 N 条路由使用」，先把路由规则改到别的映射集。

**大小写对不上。**
匹配区分大小写。Emby 里是 `/Media`，映射里写 `/media` 不会命中。

**存储里多了一层目录。**
例如对象实际在 `media/movies/阿凡达.mkv`，映射却得到 `movies/阿凡达.mkv`。可以把「存储中的路径前缀」写成 `media/movies`；S3 也可以在后端的「Key Prefix」里填 `media`，两种只选一种，不要叠加。
