# 系统日志

系统日志就是网关进程的运行日志，用来排查启动、配置加载、后端访问、STRM 同步和通知发送等问题。它和「流量分析」里的请求日志不同：请求日志记录每一个请求，系统日志记录网关自己在做什么、哪里出了错。

## 筛选日志

顶部的筛选条件可以任意组合：

| 筛选 | 说明 |
|---|---|
| Emby | 只看某个 Emby 源相关的日志；也可以直接输入已删除源的 ID 查历史，或选「无 Emby 关联 / 历史未知」 |
| 后端 | 只看某个存储后端相关的日志，用法同上 |
| 模块 | Emby 代理、Emby API、路由与重定向、后端调用、流量中转、播放会话、STRM 同步、安全防护、通知、Local Agent 同步、数据库、许可证、观测采集、系统 |
| 级别 | ERROR 错误、WARN 警告、INFO 信息、DEBUG 调试 |
| 关键词 | 在服务端按包含关系匹配日志内容 |

设置好条件后点「查询最近日志」，结果从新到旧排列，每次取一批，点「更早一批」可以继续往前看。「重置」会清空所有条件。

列表下方会显示本次扫描了多少日志、覆盖哪个时间段。如果提示「本次扫描范围有限」，说明还没有扫完全部历史，这时查不到结果不代表更早的日志里也没有，可以继续加载更早的记录。

::: tip
「历史级别未知」「历史未分类」用于筛出较早版本写下的日志，那时日志还没有带级别和模块信息。
:::

## 查看详情

点击任意一行会打开「运行日志详情」，里面有本地时间、原始时间、模块与级别、关联的 Emby 源、后端、路由和资源池，以及完整内容。

日志写入时会自动脱敏：网址、Cookie、Bearer 令牌、私钥和常见的凭据参数都会被替换成 `[redacted]` 之类的占位符。所以向别人求助时，可以放心用「复制脱敏记录」把整条日志贴出去。

## 常见日志怎么读

模块选「路由与重定向」，最适合排查「为什么没有走 302」：

| 日志内容 | 含义 | 处理 |
|---|---|---|
| `路径映射未命中（回退代理）` | 规则命中了，但路径映射里没有任何一条能转换这个路径，请求交给 Emby 代理 | 检查 [路径映射](/guide/path-mapping) 的前缀是否和 Emby 里的真实路径一致，可以用「映射测试」验证 |
| `未找到 path_rule_set` / `未找到 resource_pool` | 规则引用的路径映射或资源池不存在（多半已被删除） | 修改规则重新选择，控制台的「需要关注」也会提示 |
| `Backend=… 生成直链失败（跳过）` | 资源池里这个后端没能生成直链，网关会继续尝试下一个后端 | 到存储后端页面做连接测试，检查凭据和配额 |
| `Backend=… 未初始化（跳过）` | 后端配置有误或缺少授权，启动时没能初始化 | 检查后端配置，查看「许可证」模块是否有相关错误 |
| `Route=… regex 无效` | 路由规则里的正则写错了，这条正则会被忽略 | 修正正则表达式 |
| `direct stream: no route matched` | `/stream/...` 直接访问的路径没有匹配到任何规则，返回 502 | 检查该源的路由规则 |
| `direct stream: path mapping not matched` | `/stream/...` 路径匹配到规则，但映射失败，返回 502 | 检查路径映射 |

::: info 普通播放请求没匹配到规则时不会写日志
Emby 客户端发起的普通播放请求，如果没有匹配到任何路由规则，网关会直接把它代理给 Emby，不会记日志。要确认某个请求有没有走 302，请在 <span class="ui-path">监控 › 流量分析</span> 的「请求日志」里找到它，看状态码和 302 相关字段。
:::

## 日志文件

管理界面里看到的系统日志同时保存在网关工作目录下的 `logs/error.log`。单个文件写到 20 MB 时会自动归档，最多保留 4 个归档文件，所以不会无限增长。同一目录下还有：

| 文件 | 内容 |
|---|---|
| `logs/error.log` | 系统日志（即本页内容） |
| `logs/admin-access.log` | 管理界面和管理 API 的访问记录 |
| `logs/proxy-<Emby 源 ID>-access.log` | 每个 Emby 源的代理访问记录 |

Docker 部署时工作目录是 `/app`，日志在容器内的 `/app/logs`。示例 compose 没有挂载这个目录，需要长期保留文件时可以自行挂载。系统日志同时也会输出到标准错误，用 `docker compose logs emby-gateway` 就能看到。
