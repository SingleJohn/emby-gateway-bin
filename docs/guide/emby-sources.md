# Emby 源与路由规则

Emby 源是网关对外提供的一个 Emby 入口：网关在一个端口上监听，把普通请求转发给上游 Emby，把视频流请求按媒体路径交给对应的资源池生成直链。每个 Emby 源下面挂一组路由规则，决定"哪些路径走哪个资源池"。

第一次配置网关、新增一台 Emby 服务器，或者播放没有走 302 时，看这一页。

## 什么时候需要多个 Emby 源

一个 Emby 源对应一个监听端口和一个上游 Emby。以下情况需要新建多个：

- 有多台 Emby 服务器，每台都要经过网关；
- 同一台 Emby 想用不同端口对外，例如一个端口给家人、一个端口给外部用户，两边配置不同的路由或防护范围。

多个 Emby 源共用同一套路径映射、资源池和存储后端，路由规则各自独立。防护策略、告警规则等也可以按 Emby 源限定生效范围。

## 新建 Emby 源

<span class="ui-path">接入与路由 › Emby 源</span>

1. 点击左侧的「新建 Emby 源」。网关会自动生成 ID，默认启用，监听 `0.0.0.0`，并从 18889 起挑一个没被其他源占用的端口。
2. 在顶部填写名称（只用于界面显示）。
3. 在「Emby 上游」里填写 Emby 地址和 API Key。
4. 按需添加路由规则（见下文 [路由规则](#路由规则)）。
5. 点击底部的「保存」。

<Shot name="emby-sources" alt="Emby 源页面：左侧源列表，右侧监听配置、Emby 上游和路由规则" />

保存后立即生效，不需要重启网关：

- 只改了路由规则，网关直接换上新规则，现有连接不受影响；
- 改了监听 Host、监听端口、直链路径前缀或 Emby 上游，网关会重启这个源的监听器，连在这个端口上的客户端会断开一次；
- 停用或删除一个源，网关停止监听它的端口。

::: warning 端口被占用
如果监听端口已被其他程序占用，这个源会启动失败并被跳过，其他源和管理界面照常运行。到 <span class="ui-path">系统 › 系统日志</span> 搜索 `ProxyV2` 可以看到失败原因。
:::

## 字段说明

### 基本

| 界面 | 配置字段 | 说明 |
|---|---|---|
| 名称 | `name` | 界面显示用，可随时修改 |
| （ID，显示在名称下方） | `id` | 自动生成，被统计、日志和防护范围引用，保存后不要改 |
| 右上角开关 | `enabled` | 关闭后网关停止监听该端口 |

### 监听配置

| 界面 | 配置字段 | 默认值 | 说明 |
|---|---|---|---|
| 「监听 Host」 | `listen_host` | `0.0.0.0` | 只想本机访问时填 `127.0.0.1` |
| 「监听端口」 | `listen_port` | 新建时自动分配 | 播放器连接的端口，范围 1–65535。启用中的源端口不能重复，保存时会检查 |
| 「直链路径前缀 (Stream Path)」 | `stream_path_prefix` | `/stream` | 网关自己的直链入口，STRM 文件里的地址和本地存储、网盘中转链接都挂在这个前缀下。一般不用改，只要别和 Emby 自身的路径冲突 |

### Emby 上游

| 界面 | 配置字段 | 说明 |
|---|---|---|
| 「Host (例如 http://192.168.1.10:8096)」 | `upstream.host` | 网关访问 Emby 用的地址，带协议和端口 |
| 「API Key」 | `upstream.api_key` | 在 Emby 控制台「API 密钥」里新建一个。网关用它查询媒体的真实路径 |
| 「Base Path」 | `upstream.base_path` | Emby 配置了 URL 前缀时填写，没有就留空 |

::: danger 没有 API Key 就不会走 302
网关需要用 API Key 向 Emby 查询"这个媒体文件在哪"。Host 或 API Key 任一为空时，网关只做反向代理，所有视频都由 Emby 自己推流。
:::

### 上游状态

左侧列表里每个源会显示上游状态：延迟毫秒数表示可达，「不可达」表示网关连不上 Emby，「未检测」表示还没检测过，「停用」表示源已关闭。详情顶部的「UP」/「DOWN」标签旁有刷新按钮，点一下立即重新检测。

## 路由规则

路由规则决定一个媒体文件交给哪个资源池。每条规则包含匹配条件、一个映射集和一个资源池：

```text
媒体真实路径 ──匹配──▶ 路由规则 ──▶ 映射集（改写成存储里的路径）──▶ 资源池（生成直链）
```

网关匹配的是**媒体在 Emby 里的真实路径**（Emby 媒体信息里显示的文件路径，例如 `/mnt/media/电影/阿凡达 (2009)/阿凡达.mkv`），不是播放器请求的 URL。一个条目有多个版本时，按播放器请求的版本取路径，取不到就用第一个版本。

### 规则字段

| 界面 | 配置字段 | 新建时默认 | 说明 |
|---|---|---|---|
| 规则左侧开关 | `enabled` | 开 | 关闭的规则不参与匹配 |
| 「Priority」 | `priority` | `10` | 数字越小越先匹配 |
| 「Prefix」 | `match.real_path_prefix` | 空 | 路径前缀，可添加多个 |
| 「Regex」 | `match.real_path_regex` | 空 | 正则表达式，可添加多个 |
| 「映射集」 | `path_rule_set_id` | 未选 | 引用 [路径映射](/guide/path-mapping) 里的规则集 |
| 「资源池」 | `pool_id` | 未选 | 引用 [资源池](/guide/routing-and-pool) |
| 开关 +「强制映射」/「可选映射」标签 | `require_mapping` | 开（强制映射） | 见下文 |

没有规则时点「新增规则」，已有规则时点列表底部的「添加新规则」。每条规则右侧的上下箭头调整列表顺序，叉号删除。

::: warning 映射集和资源池都要选
规则命中后，网关要用映射集改写路径、用资源池生成直链。任何一个没选或引用的对象已被删除，这条规则都不会产生 302，请求会回退给 Emby。
:::

### 匹配方式

网关先把真实路径归一化：反斜杠 `\` 换成 `/`，去掉多余的 `/`、`.`、`..`，并保证以 `/` 开头。如果路径是 `http://`、`https://` 开头的地址，只取其中的路径部分（会先解码）。然后按下面的方式判断：

- **前缀**：按目录层级匹配。`/mnt/media` 能匹配 `/mnt/media` 和 `/mnt/media/电影/a.mkv`，**不能**匹配 `/mnt/media2/a.mkv`。区分大小写。前缀 `/` 匹配所有路径。
- **正则**：用 Go 正则语法（RE2）对归一化后的完整路径求值，只要路径中有一段符合就算命中。想从头匹配请以 `^` 开头。写错的正则会被跳过，并在系统日志里记录。
- 一条规则里的多个前缀、多个正则是"或"的关系，任意一个命中就算这条规则命中。
- 前缀和正则**都不填**，这条规则匹配全部路径，适合当兜底规则。

### 优先级与命中顺序

1. 只看启用的规则；
2. 按「Priority」数字从小到大排序，数字相同时按列表里的先后顺序（用上下箭头调整）；
3. 从第一条开始依次匹配，**第一条命中的规则生效，后面的规则不再看**。

命中之后，即使这条规则的路径映射没匹配上，或者资源池里的后端都失败了，网关也不会去试下一条规则，而是直接回退给 Emby。想做"一个目录多个存储互为备份"，请用 [资源池的备用后端](/guide/routing-and-pool)，不要写两条匹配同一路径的规则。

### 强制映射

「强制映射」（`require_mapping`）控制路径映射没匹配上时怎么办：

| 设置 | 映射集里有条目、但没有一条匹配上 |
|---|---|
| 「强制映射」（开） | 映射失败，这次请求回退给 Emby |
| 「可选映射」（关） | 不改写，直接把真实路径（去掉开头的 `/`）当作存储里的路径继续生成直链 |

如果映射集里一条映射都没有，两种设置效果相同：都按原路径继续。

一般保持「强制映射」。只有当 Emby 里的路径和存储里的路径完全一致时，才考虑用「可选映射」。

### 没有命中时会怎样

播放器请求视频时，下面任何一种情况都不会中断播放，而是**回退代理**：网关像普通反向代理一样把请求交给 Emby，由 Emby 推流。

- 没有启用的规则，或没有任何规则命中；
- 命中的规则开启了「强制映射」，但路径映射没有匹配上；
- 命中的规则引用的映射集或资源池不存在；
- 资源池里的主用、备用后端都没能生成直链；
- 网关查询 Emby 失败（上游不可达、API Key 无效等）。

回退时视频流量会经过 Emby 服务器。如果发现带宽没降下来，先用下面的「匹配测试」确认规则，再到 <span class="ui-path">系统 › 系统日志</span> 搜索 `回退代理` 查看具体原因。

有两个例外：

- 请求的是直链路径前缀（默认 `/stream`）下的地址时，没有可回退的 Emby 请求，网关直接返回 `502`，响应正文是 `no route matched`、`path mapping not matched` 或 `no backend available` 等原因。
- 资源池里使用了外部解析服务后端时，生成失败会返回 `502` 让播放器重试，不回退给 Emby，详见 [外部解析服务](/guide/backend-http-resolver)。

### 被遮蔽的规则

兜底规则（不填任何条件，或前缀是 `/`）如果排在其他规则前面，它后面的规则永远不会命中。管理界面会检查这种情况，在控制台的「需要关注」、顶栏的「需要关注」铃铛和「使用说明」页提示：

> 该规则匹配全部路径且优先级为 10，其后 2 条规则（…）永远不会命中；请把兜底规则的优先级数字调大

处理办法：把兜底规则的「Priority」改成一个比其他规则都大的数字，例如 `1000`。

同一处检查还会提示规则引用了不存在的映射集、资源池或后端。

### 匹配测试

「路由规则」标题下方有一个「匹配测试」输入框，用来在保存前确认一条路径会走哪条规则。

<Shot name="route-test" alt="匹配测试：输入真实路径后显示命中的规则、映射集和资源池" />

1. 到 Emby 里打开一部影片的媒体信息，复制文件路径；
2. 粘贴到「匹配测试」输入框；
3. 看结果：
   - 命中时显示「命中规则」和规则 ID，括号里是命中原因（哪个前缀、哪个正则，或"未设置匹配条件，匹配全部路径"）和优先级，下一行是这条规则的映射集和资源池；
   - 没命中时提示请求将「回退到反代」，如有无效正则会一并列出；
   - 最后一行「归一化路径」是网关实际拿去匹配的路径。

测试按**当前编辑中**的规则计算，不需要先保存。它只判断走哪条规则，路径映射的结果请到 [路径映射](/guide/path-mapping#映射测试) 的「映射测试」里看。

::: tip 正则测试结果
测试在浏览器里用 JavaScript 正则计算，常见写法与网关一致。如果用了前瞻、反向引用等 RE2 不支持的语法，测试可能显示命中，但网关会把这条正则当作无效跳过。
:::

## 配置示例

电影放在 S3，剧集放在 115，其余照常由 Emby 推流：

| Priority | Prefix | 映射集 | 资源池 | 映射 |
|---|---|---|---|---|
| 10 | `/mnt/media/电影` | 电影映射 | S3 电影池 | 强制映射 |
| 20 | `/mnt/media/剧集` | 剧集映射 | 115 剧集池 | 强制映射 |

两条规则的前缀互不重叠，不在这两个目录下的文件不命中任何规则，自动回退给 Emby。

如果希望所有文件都尽量走直链，再加一条兜底规则：「Priority」填 `1000`，前缀和正则都不填，映射集和资源池指向你的默认存储。

## 常见问题

**播放器连网关端口能看到媒体库，但播放没有走 302。**
依次检查：Emby 上游的 API Key 是否填了；用「匹配测试」确认路径能命中规则；规则的映射集、资源池是否都选了；到路径映射页用「映射测试」确认能匹配上；最后在系统日志里搜索 `回退代理`。

**改了端口后客户端连不上。**
改端口会让这个源在新端口重新监听，客户端要改用新端口；用 Docker 部署时还要同步修改端口映射。

**两条规则优先级一样，哪条先？**
按列表里的顺序，排在上面的先。用规则右侧的上下箭头调整。

**正则匹配不到，前缀却可以。**
正则是对整条归一化路径求值的，路径里的 `(`、`)`、`.`、`[` 等字符在正则中有特殊含义，需要转义。先在「匹配测试」里看「归一化路径」，再对照着写。
