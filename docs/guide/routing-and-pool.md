# 资源池与故障切换

资源池是路由规则和存储后端之间的一层：路由规则指向资源池，资源池里放一个主用后端和一个可选的备用后端。播放时网关先用主用后端生成直链，失败了再试备用后端。

同一份媒体放在两个存储里、想让一个出问题时自动用另一个，或者想以后整体换存储而不改路由规则时，看这一页。

## 字段

<span class="ui-path">接入与路由 › 资源池</span>

| 界面 | 配置字段 | 说明 |
|---|---|---|
| 资源池名称 | `resource_pools[].name` | 界面显示用 |
| （名称下方的 ID） | `resource_pools[].id` | 自动生成，路由规则通过它引用 |
| 「主用后端」 | `primary_backend_id` | 必填，每次播放都先用它 |
| 「备用后端」 | `standby_backend_id` | 可选，主用后端失败时使用 |

每个资源池只有这两个位置，没有权重、轮询或单独的启用开关。想按目录分到不同存储，就建多个资源池，由不同的路由规则引用。

后端选择框旁的标签显示后端状态：后端类型（正常）、「已停用」、「后端不存在」或「未设置」。已停用的后端在下拉框里显示为「（已停用）」，不能选。点「配置」跳到该后端的详情。卡片底部显示「被 N 条路由使用」。

## 新建资源池

1. 先在 [存储后端](/guide/backend-configuration) 里建好后端，并确认连接正常。
2. 点击右上角「新建资源池」，填写名称。
3. 「主用后端」选主力存储；有第二份副本时，「备用后端」选它。
4. 点击底部「保存」，立即生效。
5. 到 [Emby 源的路由规则](/guide/emby-sources#路由规则) 里，在「资源池」下拉框选中它。

::: warning 主备要能用同一个路径找到文件
主用和备用后端收到的是**同一个存储路径**（路径映射的结果）。两边的目录结构必须一致，否则切到备用时一样找不到文件。路径映射见 [路径映射](/guide/path-mapping)。
:::

## 什么时候切到备用

每次播放请求，网关都按"主用 → 备用"的顺序尝试，遇到下面任一情况就跳过当前后端、试下一个：

- 位置没有选后端；
- 后端没有初始化成功：已停用、必填字段缺失（例如 S3 没填 Access Key）、或授权不包含这种后端类型；
- 后端生成直链时报错。

拿到第一个可用的直链就返回 `302`，不再往下试。

### "生成直链失败"取决于后端类型

网关只在**生成直链的那一刻**判断成败，所以能检测到什么故障，取决于这种后端生成直链时做了什么：

| 后端类型 | 生成直链时 | 能触发切换的典型情况 |
|---|---|---|
| S3 对象存储、阿里云 CDN、本地存储、Local Agent 代理，以及「直链模式」为「拼接直链」的 123 网盘 Open | 在网关本地计算签名或拼接地址，不查询文件 | 基本只有配置错误。存储宕机、文件不存在都**不会**触发切换 |
| Google Drive、「API 获取直链」模式的 123 网盘 Open、115 网盘 Open、115 网盘 Cookie、115 分流聚合、外部解析服务 | 调用网盘或解析服务的接口查找文件、获取下载地址 | 接口报错、超时、凭据失效、文件不存在 |

也就是说，"CDN 做主用、S3 做备用"这种组合，CDN 回源出问题时网关不会自动改用 S3，因为 CDN 签名在本地就成功了。

### 302 之后的故障网关看不到

网关返回 `302` 后，播放器直接去存储拉流。之后存储返回 403、404 或连接超时，网关都不知道，也不会再换备用。播放器重新发起播放时，网关会重新从主用后端开始尝试。

### 会不会切回主用

不需要切回。网关不记录"主用已故障"的状态，也没有健康检查或熔断：**每一次播放请求都重新从主用后端开始**。主用恢复后，下一次播放自然就用主用。

反过来，主用持续故障时，每次播放都会先在主用上失败一次再转到备用。网盘类后端的接口超时会直接加到起播时间上，此时可以临时把两个后端对调，或者停用主用后端。

::: tip 123 转码会话
使用 123 网盘按需转码时，一个播放会话开始后会固定在当时使用的后端上，避免同一个流里混入原片和转码片段。详见 [123 转码](/guide/pan123-transcode)。
:::

## 302 与网关中转在故障时的差异

115 系列后端的「链路模式」可选「302 重定向」或「网关中转 (Relay)」；外部解析服务也有类似的中转选项。两种模式在生成直链阶段完全一样，都会先向网盘接口取下载地址，所以切换备用的时机相同。区别在拿到地址之后：

| | 「302 重定向」 | 「网关中转 (Relay)」 |
|---|---|---|
| 播放器拿到的地址 | 网盘的下载地址 | 网关自己的中转地址（在直链路径前缀下） |
| 视频流量 | 播放器直连网盘，不经过网关 | 经过网关转发，占用网关带宽，计入网关流量统计 |
| 拉流过程中网盘出错 | 网关看不到 | 网关返回 `502`（`relay request failed`），**不会**改用备用 |
| 中转地址过期后再访问 | 不适用 | 网关返回 `410`（`expired or invalid token`），需要重新播放 |

两种模式都只在生成链接时做主备切换，中转模式并不会在传输中途切换后端。各类型的详细说明见 [115 网盘](/guide/backend-115) 和 [外部解析服务](/guide/backend-http-resolver)。

## 主备都失败时

| 请求来源 | 结果 |
|---|---|
| 播放器正常播放（经 Emby 的视频流接口） | **回退代理**：请求交给 Emby，由 Emby 推流，播放不中断 |
| 直链路径前缀（默认 `/stream`）下的请求，例如 STRM 文件 | 返回 `502`，正文 `no backend available` |
| 资源池里有外部解析服务后端 | 返回 `502` 并提示"播放源准备失败，请重新发起播放。"，不回退给 Emby |

回退给 Emby 意味着这次播放的流量走了 Emby 服务器。如果 Emby 本身读不到这个文件（例如媒体只存在于网盘、Emby 里只有 STRM），回退后同样播不了。

## 完整示例

电影在 123 网盘和 115 各存一份，以 123 为主；剧集只在 S3。

**存储后端**

| 名称 | 类型 |
|---|---|
| 123 主力 | 123 网盘 Open |
| 115 备份 | 115 网盘 Open |
| S3 剧集 | S3 对象存储 |

**资源池**

| 名称 | 「主用后端」 | 「备用后端」 |
|---|---|---|
| 电影池 | 123 主力 | 115 备份 |
| 剧集池 | S3 剧集 | （不选） |

**路径映射**：规则集"电影"把 `/mnt/media/电影` 映射为 `电影`，规则集"剧集"把 `/mnt/media/剧集` 映射为 `tv`。123 和 115 网盘里都要有 `电影/...` 这套目录。

**路由规则**（在 Emby 源里）

| 「Priority」 | 「Prefix」 | 「映射集」 | 「资源池」 |
|---|---|---|---|
| 10 | `/mnt/media/电影` | 电影 | 电影池 |
| 20 | `/mnt/media/剧集` | 剧集 | 剧集池 |

效果：

- 播放电影时先向 123 取直链（123 后端用「API 获取直链」模式）；123 接口报错或找不到文件时，改向 115 取直链；两个都失败则回退给 Emby。
- 播放剧集时只用 S3 签名。S3 只要配置正确就会签名成功，桶不可用也不会回退，播放器会在拉流时报错。
- 两个目录以外的文件不命中任何规则，由 Emby 推流。

保存后播放几次，到 <span class="ui-path">监控 › 流量分析</span> 的「302 链路」里看各后端的「尝试」次数和「成功率」，确认备用后端是否被用到。

## 常见误区

- **"备用后端会在主用宕机后接管，直到手动切回。"** 不会。没有状态，每次播放都从主用开始。
- **"S3 / CDN 桶挂了会切到备用。"** 不会。这几类后端在本地签名，签名成功就返回 302，存储的可用性网关检测不到。
- **"主用、备用都失败时网关会提示无可用后端。"** 正常播放时会回退给 Emby 推流，不报错；只有直链路径前缀下的请求才返回 `502 no backend available`。
- **"一个路由失败后会去试下一条路由。"** 不会。第一条命中的路由生效，后面的路由不再尝试。想要两级存储请用备用后端。
- **"资源池可以放更多后端做负载均衡。"** 只有主用、备用两个位置。要在多个 115 账号之间分摊流量，用 [115 分流聚合](/guide/backend-115)。
- **"中转模式更可靠，出错会自动换线。"** 中转只是由网关转发数据，传输中出错同样不会换备用后端。

## 常见问题

**删除资源池会怎样？**
删除前会提示有多少条路由在用它。删除并保存后，这些路由找不到资源池，播放全部回退给 Emby。

**后端在资源池里显示「后端不存在」。**
资源池引用的后端已被删除。重新选择一个后端，或者从 [存储后端](/guide/backend-configuration) 重新创建。控制台的「需要关注」也会列出这类引用失效。

**能不能只配备用、不配主用？**
可以保存，但每次都会先跳过空的主用位置，效果等同于把它设成主用。建议直接放在主用位置。
