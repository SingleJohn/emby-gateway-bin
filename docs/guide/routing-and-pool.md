# 路由规则和资源池

路由负责回答“这个媒体路径使用哪个资源池”，资源池负责回答“先尝试哪个后端，失败后尝试哪个后端”。

## 当前数据模型

### 路由规则

每条路由包含：

- `id`、启用状态和 `priority`
- 真实路径前缀列表和正则列表
- 一个路径映射集
- 一个资源池
- 是否强制路径映射

路由按 `priority` 从小到大匹配；相同优先级保持配置顺序。前缀和正则中的任意一项匹配即命中，两者都为空时是全匹配兜底规则。

### 资源池

每个资源池只包含：

- 一个必选主后端 `primary_backend_id`
- 一个可选备后端 `standby_backend_id`

当前版本不支持以下能力：

- 多个主后端
- 多个备后端
- 后端权重
- 资源池内轮询或按比例负载均衡
- 资源池单独的启用开关

需要按内容分流时，应创建多个资源池，再通过不同路由分别引用。

## 推荐配置顺序

1. 在「资源池与后端」中创建并验证后端。
2. 创建资源池，选择主后端和可选备后端。
3. 在「路径映射」中创建映射集。
4. 在「Emby 源」中新增路由并绑定映射集和资源池。
5. 保存后发起一次真实播放，在「流量分析 → 302 链路」查看决策结果。

## 主备切换

命中路由后，网关只在该路由绑定的资源池内尝试：

```text
主后端生成直链成功 -> 返回 302
        |
        +-- 失败 -> 备后端生成直链成功 -> 返回 302
                         |
                         +-- 失败或未配置 -> 回退 Emby 代理
```

这里的“失败”指后端适配器无法为当前 object key 生成可用 URL，并不等同于持续健康检查或自动摘除节点。

## 路由失败后的行为

路由一旦命中，后续映射或后端失败不会再尝试下一条路由。

如果必须让不同后端处理不同媒体范围，请让前缀或正则互斥，并准备一个最低优先级的全匹配兜底路由。不要把多条同路径路由当作多级故障转移。

## 配置示例

假设电影优先使用 CDN，失败时回源 S3：

```text
后端：cdn-primary、s3-backup
资源池：movies-pool
  主后端：cdn-primary
  备后端：s3-backup
路由：movies-route
  priority：10
  前缀：/media/movies/
  映射集：movies-map
  资源池：movies-pool
```

再添加一个兜底路由：

```text
路由：default-route
  priority：1000
  前缀和正则：留空
  资源池：default-pool
```

## 常见误区

- **按请求 URL 匹配**：路由实际匹配 Emby 解析出的真实媒体路径。
- **优先级越大越先执行**：实际是数字越小越先匹配。
- **主后端失败会尝试下一条路由**：实际只尝试当前资源池的备后端。
- **同优先级按路径长度决定**：实际保持配置中的原始顺序。
- **配置多个后端就会负载均衡**：资源池只有固定主备关系。

精确匹配与回退语义参见 [路由匹配规则详解](/guide/route-matching-rules)。
