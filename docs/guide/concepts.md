# 核心概念

本页解释文档和管理界面里反复出现的术语，以及这些对象之间怎么串起来。配置前读一遍，后面各页的字段会更好理解。

## 对象之间的关系

一次播放请求从 Emby 源进来，依次用到下面几个对象：

```text
播放器
  │  连接监听端口
  ▼
Emby 源 ──(查询真实路径)──▶ 上游 Emby
  │  路由规则：按优先级匹配真实路径
  ▼
路由规则 ──引用──▶ 路径映射规则集：真实路径 → 存储里的路径
  │
  └──引用──▶ 资源池 ──▶ 主用后端（失败时）──▶ 备用后端
                              │
                              ▼
                       302 直链 / 中转
```

| 对象 | 归属 | 被谁引用 | 在哪里配置 |
|---|---|---|---|
| Emby 源 | 顶层 | 播放器直接连接 | <span class="ui-path">接入与路由 › Emby 源</span> |
| 路由规则 | 属于某个 Emby 源 | 只在本源内生效 | 同上，「路由规则」分区 |
| 路径映射规则集 | 顶层 | 路由规则的「映射集」 | <span class="ui-path">接入与路由 › 路径映射</span> |
| 资源池 | 顶层 | 路由规则的「资源池」 | <span class="ui-path">接入与路由 › 资源池</span> |
| 存储后端 | 顶层 | 资源池的「主用后端」「备用后端」，以及 STRM 任务、对象浏览 | <span class="ui-path">接入与路由 › 存储后端</span> |

规则集、资源池和存储后端都可以被多处复用：多个 Emby 源的路由规则可以指向同一个资源池，同一个后端也可以出现在多个资源池里。

## 接入

### Emby 源

网关对外提供的一个 Emby 入口。每个 Emby 源有自己的「监听端口」，并指向一个上游 Emby 服务器，播放器把服务器地址填成网关的这个端口即可。网关用源里配置的 API Key 向 Emby 查询媒体的真实路径，没有 API Key 时不会生成直链。见 [Emby 源与路由规则](/guide/emby-sources)。

### 真实路径

媒体文件在 Emby 媒体库里记录的路径，例如 `/mnt/media/movies/阿凡达.mkv`。路由规则和路径映射都基于它工作。如果 Emby 里的条目是 `.strm` 文件，真实路径就是文件里写的地址，网关取其中的路径部分来匹配。

### 回退代理

请求没有走直链时，网关把它原样转发给上游 Emby，界面上也叫「回退到反代」。登录、浏览、图片等非媒体流请求始终走这条路；媒体流请求在没命中路由、映射失败或后端都不可用时也会回退，保证能继续播放。见 [介绍与工作原理](/guide/introduction#什么时候回退代理)。

## 路由

### 路由规则

决定一个媒体流请求交给哪个资源池。每条规则有匹配条件（路径前缀 Prefix 或正则 Regex，两者都不填表示匹配所有路径）、优先级、映射集和资源池。规则按优先级数字从小到大匹配，第一条命中即停止。见 [Emby 源与路由规则](/guide/emby-sources#路由规则)。

### 强制映射

路由规则上的开关，新增规则时默认开启。开启后，如果规则集里有映射但一条都没匹配上，这条路由不会生成直链，请求回退给 Emby；关闭时没匹配上就按原路径去存储里找。

### 路径映射（规则集）

把 Emby 里的路径前缀换成存储里的路径前缀，例如 `/mnt/media/movies` → `/movies`。若干条映射组成一个规则集，按列表顺序取第一条命中的映射；前缀按整段目录匹配、区分大小写。转换结果去掉开头的 `/` 后就是交给后端的对象 Key。见 [路径映射](/guide/path-mapping)。

### 资源池

一个「主用后端」加一个可选的「备用后端」。生成直链时先试主用，失败再试备用，两者应当存放相同的内容。没有被任何路由规则引用的资源池不参与播放。见 [资源池与故障切换](/guide/routing-and-pool)。

## 存储与交付

### 存储后端

媒体实际存放的地方，以及访问它所需的凭据。支持 S3 对象存储、阿里云 CDN、123 网盘、115 网盘（Open、Cookie、分流聚合）、Google Drive、本地存储、Local Agent 和外部解析服务。不同类型的直链有效期、缓存和交付方式各不相同。见 [后端总览](/guide/backend-configuration)。

### 302 直链

网关为对象生成一个可直接下载的地址（例如带签名的 S3 链接或网盘下载链接），用 HTTP `302` 让播放器跳转过去。视频数据从此在播放器和存储之间传输，不经过网关和 Emby 服务器。这是网关的默认交付方式。

### 中转

也叫 Relay：网关自己去存储取数据，再转发给播放器，地址走 Emby 源的「直链路径前缀 (Stream Path)」（默认 `/stream`）。适合存储只对网关可达、或直链对播放器有限制的情况，代价是视频流量经过网关。115 系列和外部解析服务可以在后端里选择中转，本地存储由网关直接提供文件。

### STRM

`.strm` 是一种只包含一个播放地址的文本文件，Emby 可以把它当作视频入库。媒体只存在网盘或对象存储里、Emby 无法直接扫描时，用 STRM 任务扫描存储后端，批量生成与目录结构对应的 `.strm` 文件给 Emby 入库。播放时请求同样经过网关的路由和映射。见 [STRM 任务](/guide/strm-guide)。

## 管理

### 管理端口

管理界面和管理 API 监听的端口，默认 `18888`，与播放器使用的 Emby 源端口分开。只应在内网或受控环境里访问。见 [部署与升级](/guide/deployment#端口规划)。

### 管理员与只读访客

用「Admin Password」登录的是管理员，可以修改全部配置；用「Viewer Password」登录的是只读访客，只能查看，配置里的密钥会被隐藏。没有设置 Admin Password 时管理界面不需要登录。见 [管理界面基础](/guide/management-ui#登录与角色)。

### 授权

网关需要激活授权才能保存 Emby 源和存储后端、生成直链。激活后由后台自动续租。见 [授权](/guide/license)。
