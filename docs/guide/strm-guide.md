# STRM 任务

STRM 任务会扫描存储后端里的媒体目录，为每个视频生成一个 `.strm` 文件（内容是一条播放地址），写到网关所在机器的本地目录。Emby 把这个目录加为媒体库，就能在不挂载网盘或对象存储的情况下完成扫库；播放时 Emby 读取 `.strm` 里的地址，请求会回到网关，由网关返回直链。

适合这些情况：

- 媒体放在 S3、123、115 等远端存储上，不想（或不能）在 Emby 服务器上挂载；
- 想让 Emby 扫库只读本地小文件，避免扫库时大量访问网盘接口。

STRM 功能需要授权中包含 STRM。没有该功能时，任务不会自动运行，手动同步也会失败。详见 [授权](/guide/license)。

## 支持的后端

| 后端类型 | 生成 STRM | 下载元数据 |
| --- | --- | --- |
| S3（`s3`） | 支持 | 支持 |
| 本地目录（`local`） | 支持 | 支持 |
| Local Agent（`local_agent`） | 支持 | 支持 |
| 123 网盘（`pan123`） | 支持 | 支持，通过直链下载 |
| 115 开放平台（`115_open`） | 支持 | 支持，通过直链下载 |

其他类型的后端不能用作 STRM 任务的来源。123 和 115 的元数据要逐个通过直链下载，速度较慢、会消耗流量，也受网盘限速和鉴权影响，界面上勾选「下载元数据」时会给出提醒。

## 新建任务

1. 点击页面右上角「新增任务」。
2. 填写下面的字段，点击「保存」。任务保存进配置后才能运行。

### 基本字段

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| 名称 | `name` | 任务名称。用「选择」挑选媒体目录时，会自动填成目录名。 |
| 后端 | `backend_id` | 从哪个存储后端读取媒体，必填。 |
| 媒体目录 | `source_prefix` | 只扫描后端里的这个目录，例如 `movies/`。留空表示整个后端。 |
| 链接目录 | `output_dir` | `.strm` 文件写到网关所在机器的哪个目录，必填，例如 `data/strm`。目录不存在时会自动创建。 |
| Base URL | `base_url` | 写进 `.strm` 的地址前缀，见下文 [STRM 文件里写的是什么](#strm-文件里写的是什么)。 |
| 同步间隔(秒) | `sync_interval_seconds` | 自动同步的间隔，界面最小 10 秒。没有填或填 0 时按 300 秒处理。 |
| 保留媒体目录 | `output_under_source_path` | 开启后输出路径是「链接目录 + 媒体目录」，例如链接目录 `/StrmOne`、媒体目录 `media/me3/电影/` 时，文件写到 `/StrmOne/media/me3/电影/` 下。 |

### 同步选项

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| 去掉源扩展名 | `strip_source_extension` | 开启时 `电影.mkv` 生成 `电影.strm`；关闭时生成 `电影.mkv.strm`。 |
| 删除失效文件 | `prune_deleted` | 存储里已删除的文件，对应的本地 `.strm` 和元数据也删除。只在一轮完整扫描结束后执行。 |
| 启用 | `enabled` | 关闭后不再自动同步。 |
| STRM 后缀 | `video_extensions` | 哪些扩展名算视频，默认包含 `.mp4` `.mkv` `.ts` `.iso` `.rmvb` `.avi` `.mov` `.mpeg` `.mpg` `.wmv` `.3gp` `.asf` `.m4v` `.flv` `.m2ts` `.tp` `.f4v`。 |

### 下载元数据

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| 并发线程数 | `concurrency` | 同时处理文件的线程数，默认 8，最大 64。生成 `.strm` 和下载元数据都受它限制。 |
| 下载元数据 | `download_metadata` | 把海报、NFO、字幕等文件一并下载到链接目录。 |
| 覆盖已有文件 | `overwrite_existing` | 本地已存在同名元数据文件时是否重新下载。关闭时跳过已存在的文件。 |
| 元数据后缀 | `metadata_extensions` | 哪些扩展名算元数据，默认 `.nfo` `.jpg` `.jpeg` `.png` `.svg` `.ass` `.srt` `.sup` `.mp3` `.flac` `.wav` `.aac`。 |

### 按子目录批量创建

媒体目录下有很多子目录（例如按片单分好的文件夹），想每个子目录一个任务时：

1. 在「媒体目录」旁点「选择」，进入上一级目录。
2. 点击「按子目录批量创建任务」，当前目录下的每个子目录都会生成一个任务，名称取子目录名。
3. 如果还没填后端和链接目录，表单顶部会提示有多少个待定任务；填好参数后点「保存」，参数会应用到全部待定任务。

## STRM 文件里写的是什么

每个 `.strm` 文件里只有一行地址，由「Base URL」加上文件在后端里的路径（媒体目录 + 相对路径）拼成，路径中的特殊字符会做 URL 编码。

- **填写 Base URL**：写成完整地址。通常填某个 Emby 源的直链入口，即 `http://网关地址:Emby 源端口` 加上该源的直链路径前缀（默认 `/stream`），例如 `http://gw:18889/stream/`。
- **Base URL 留空**：写成以 `/` 开头的路径，例如 `/电影/xxx.mp4`，适合由反向代理按路径转发的部署。

Emby 播放时请求这个地址，网关按 [路由规则](/guide/emby-sources#路由规则)、[路径映射](/guide/path-mapping) 和 [资源池](/guide/routing-and-pool) 找到存储并返回直链。也就是说，`.strm` 里的路径也要能被路由规则匹配到。通过直链入口进来的请求如果没有匹配的路由规则，会直接返回错误，不会代理给 Emby。

## 在 Emby 里使用

1. 确认 Emby 能读到链接目录。网关跑在 Docker 里时，要把链接目录挂载出来，再挂到 Emby 容器里。
2. 在 Emby 中新建媒体库，文件夹选择链接目录（或其中的子目录）。
3. 第一次同步完成后，在 Emby 中扫描媒体库。之后新增的文件，等下一次同步写入 `.strm` 后，再由 Emby 的定时扫描或实时监控入库。

## 任务卡片

每个任务一张卡片，显示：

- **状态**：「运行中」「排队中」「空闲」「上次失败」「已停用」；还没保存的任务显示「未保存」。
- **目录**：媒体目录 → 链接目录。
- **上次运行**：完成时间（运行中时显示开始时间），以及扫描、写入、删除、错误四个数字；有错误时用红色显示最后一条错误信息。
- **同步间隔**：卡片底部的「每 N 自动同步」。

卡片上的操作：

- **立即同步**：马上把任务加入队列。只有已保存的任务才能同步。
- **更多**菜单：
  - 「编辑任务」：修改参数后保存。
  - 「刷新状态」：重新读取这个任务的运行状态。
  - 「重置进度并全量重扫」：清空增量进度，从头扫描整个媒体目录，见下文。
  - 「删除任务」：删除后不再同步；已生成的 `.strm` 文件不会被清理，需要的话手动删除链接目录。

## 增量同步与全量重扫

- **所有任务共用一个队列**，同一时间只运行一个任务。任务正在排队时再次触发，不会重复入队。
- **分批扫描**：每次运行处理的分页数有上限（30 页），目录很大时，一轮完整扫描会分几次运行完成，每次从上次停下的位置继续。
- **只写有变化的文件**：`.strm` 内容没变的文件会跳过，不计入写入数。
- **删除在一轮扫完后进行**：开启「删除失效文件」时，只有一轮完整扫描结束，才会清理本轮没再出现的文件。
- **换了后端会重新开始**：修改任务的后端，或后端的工作方式变了，增量进度会自动清空，从头扫描。

「重置进度并全量重扫」会丢弃当前的扫描位置，立即重新入队，从头扫描整个媒体目录。它会产生较多的网盘或对象存储 API 调用，目录大时耗时较长。任务正在运行时不能重置。

## 运行记录

「运行记录」Tab 列出最近的运行，可以按任务筛选，打开「显示运行中」可同时看到正在运行的任务。表格里有触发方式（自动或手动）、模式、轮次、页数、API 调用次数、写入、删除、错误、耗时、开始和结束时间、最后错误。

点击「详情」查看这次运行逐个文件的处理结果：`written`（写入）、`skipped`（跳过）、`deleted`（删除）、`error`（出错），元数据对应 `meta_written`、`meta_skipped`、`meta_deleted`、`meta_error`，并带有对象键、本地路径和错误信息。

## 常见问题

**任务一直显示「状态未知」或不运行**

先确认任务已保存且「启用」已打开，再确认授权中包含 STRM 功能，以及后端本身是启用状态。后端被停用或删除时，运行会以错误结束。

**Emby 里播放 STRM 失败**

用浏览器打开某个 `.strm` 里的地址试试。返回错误时，到 <span class="ui-path">接入与路由 › Emby 源</span> 用「路由匹配测试」检查这个路径有没有命中规则，再检查路径映射。

**写入数一直是 0**

内容没有变化的文件会被跳过，这是正常的。想强制重写，可以清空链接目录后执行「重置进度并全量重扫」。

**元数据下载很慢**

123 和 115 的元数据要逐个走直链下载。可以只保留真正需要的「元数据后缀」，或关闭「下载元数据」，让 Emby 自己刮削。
