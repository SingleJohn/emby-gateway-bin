# 告警规则与告警记录

[防护策略](/guide/security) 负责自动拦截，告警规则负责**通知你**：用户被自动封禁、某个账号访问异常频繁、同一账号出现在大量 IP 上、错误率突然升高……命中规则后，网关通过 [通知渠道](/guide/notification) 推送消息，并在告警记录里留下每一次的投递结果。

入口：<span class="ui-path">安全 › 告警规则</span>

<Shot name="security-alerts" alt="告警规则页面，顶部是安全告警总开关，下方是检查与投递设置和规则列表" />

## 让告警发得出去

告警要真正送达，需要同时满足：

1. 告警规则页顶部的「安全告警总开关」已打开；
2. [通知渠道](/guide/notification) 页的通知总开关已打开，且至少有一个启用的渠道；
3. 规则本身已启用，并选择了通知渠道；
4. 授权中包含安全告警功能（见 [授权](/guide/license)）。

告警规则页的「检查与投递」区会显示通知投递状态：「总开关已关闭」「无可用渠道」或「N 个渠道可用」。通知总开关不在这里改，点「管理通知渠道 →」去通知渠道页设置。

「执行周期（秒）」是网关检查所有规则的间隔，默认 60 秒，最小 10 秒。

## 告警类型

点「新建规则」，先选「告警类型」：

| 告警类型 | 配置值 | 什么时候触发 |
| --- | --- | --- |
| 自动封禁通知（每次处罚一次） | `user_protection` | 用户被自动防护临时封禁时，每次处罚通知一次，同一次处罚之后的拦截不再重复通知。 |
| 成功访问频率 | `user_frequency` | 统计窗口内，同一用户（或同一 IP）**成功放行**的请求数达到阈值。 |
| 成功访问身份漂移 | `identity_drift` | 同一用户出现在过多 IP 上，或同一 IP 上出现过多用户，或 User-Agent 种类过多。 |
| 异常失败率 | `failure_rate` | 请求数达到最低值后，4xx / 5xx 的比例超过阈值。 |
| 拦截事件频率 | `security_event_frequency` | 统计窗口内被拦截、被限流的事件数达到阈值。 |

「成功访问频率」和「成功访问身份漂移」只统计 2xx / 3xx 请求。401、403、429 这类已被拒绝的请求，用「拦截事件频率」单独告警。

## 规则字段

### 基本信息

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| 规则名称 | `name` | 出现在通知标题和告警记录里，例如「同一用户多 IP 告警」。 |
| 告警类型 | `type` | 见上表。 |
| 统计维度 | `group_by` | 按什么分组计数，见下文。 |
| 启用规则 | `enabled` | 关闭后不再检查。 |

统计维度：

- 成功访问频率、身份漂移、异常失败率：「按用户」（`emby_user_id`）或「按 IP」（`client_ip`）。
- 拦截事件频率：「按 IP」「按规则」（`rule_name`）「按 Source」（`source_id`）「按决策类型」（`decision`，即拦截还是限流）。
- 自动封禁通知固定按用户。

### 触发条件

| 字段 | 配置键 | 适用类型 | 说明 |
| --- | --- | --- | --- |
| 请求范围 / 处罚触发范围 | `request_scope` | 全部 | 全部请求、普通 API 或媒体请求。 |
| 统计窗口（秒） | `window_seconds` | 全部 | 统计最近多长时间，最小 60 秒，新建默认 3600。 |
| 冷却时间（秒） | `cooldown_seconds` | 除自动封禁通知外 | 同一个对象发过告警后，多久内不再重复发，新建默认 1800。填 0 表示不设冷却。 |
| 请求数阈值 | `user_frequency.max_requests` | 成功访问频率 | 默认 200。 |
| 拦截事件数阈值 | `user_frequency.max_requests` | 拦截事件频率 | 默认 100。 |
| 最小请求数 | `identity_drift.min_total` | 身份漂移 | 请求数不到这个值时不判断，默认 50。 |
| 同一用户的 IP 数阈值 | `identity_drift.max_unique_ips` | 身份漂移，按用户 | 默认 5。 |
| 同一 IP 的用户数阈值 | `identity_drift.max_unique_users` | 身份漂移，按 IP | 默认 5。 |
| UA 数阈值 | `identity_drift.max_unique_uas` | 身份漂移 | 默认 5。 |
| 最小请求数 | `failure_rate.min_total` | 异常失败率 | 默认 50。 |
| 失败率阈值（0–1） | `failure_rate.max_error_rate` | 异常失败率 | 默认 0.3，即 30%。 |

身份漂移在满足最小请求数后，IP 数（或用户数）、UA 数任一达到阈值即触发。

自动封禁通知没有冷却时间：网关按窗口查询新增的处罚，发送成功后会记下来，网关重启后也不会对同一次处罚重复通知。

### 通知与适用范围

- **通知渠道**（`channels`）：可以多选。没有选择渠道的规则不会发送提醒。
- **适用 Source**（`scope.source_ids`）：只统计选中的 Emby 源，留空表示全部。

编辑完点「应用到草稿」，再在页面底部保存，规则才会生效。

## 告警记录

每次规则触发都会记录一条，可以从告警规则页右上角「查看告警记录 →」进入，或在 <span class="ui-path">安全 › 防护记录</span> 打开「告警记录」Tab。

<Shot name="alert-records" alt="告警记录列表，显示规则、告警对象、Emby 源和各渠道投递结果" />

每条记录包括：

- 时间、告警规则和类型、告警对象（例如用户 ID 或 IP）、Emby 源；
- 投递结果：「已送达」「部分送达」或「投递失败」，并列出成功和失败的渠道；
- 展开后可以看到通知的标题和正文原文，以及每个失败渠道的错误信息。

可以按「全部」「已送达」「投递失败」切换，也可以按规则或关键词查询。

几个细节：

- 投递失败时，网关会在之后的检查周期里继续重试；同一条告警的失败记录，**10 分钟内只记一次**，避免刷屏。
- 近 24 小时内有投递失败时，控制台的「需要关注」和顶栏铃铛会提示，点击直接进入失败的告警记录。
- 告警记录保留 90 天。

## 推荐的起步规则

| 想知道的事 | 告警类型 | 建议设置 |
| --- | --- | --- |
| 谁被自动封禁了 | 自动封禁通知 | 直接启用，选一个手机能收到的渠道 |
| 账号是否被多人共用 | 成功访问身份漂移，按用户 | 窗口 3600 秒，IP 数阈值 5 |
| 有没有人在刷接口 | 拦截事件频率，按 IP | 窗口 600 秒，阈值 100 |
| 上游或存储是否出故障 | 异常失败率，按用户 | 最小请求数 50，失败率 0.3 |

先用较宽松的阈值跑几天，根据告警记录里的实际情况再收紧，避免一开始被消息淹没。
