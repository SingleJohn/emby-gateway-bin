# 通知渠道

通知渠道决定告警消息发到哪里。[告警规则](/guide/security-alerts) 命中后，会发往规则里选中的、且已启用的渠道。目前支持五种渠道：

| 渠道 | 配置值 | 适合 |
| --- | --- | --- |
| 企业微信 Webhook | `wecom_webhook` | 企业微信群机器人 |
| 钉钉机器人 | `dingtalk` | 钉钉群自定义机器人 |
| Telegram Bot | `telegram_bot` | Telegram 个人或群组 |
| Bark | `bark` | iOS 推送 |
| Server 酱 | `serverchan` | 推送到微信 |

入口：<span class="ui-path">系统 › 通知渠道</span>

## 通知总开关

页面顶部的通知总开关控制**所有**通知，包括安全告警。关闭时显示「通知发送已关闭」，任何渠道都不会发送消息。

总开关旁边汇总了：启用的渠道数、近 7 天发出的告警条数，以及其中未送达的条数。点「查看告警记录 →」可以看到每一条告警的投递明细。

## 新增渠道

1. 点击页面右上角「新增渠道」，列表里会多出一个展开的渠道卡片。
2. 在卡片顶部填写别名（例如「运维群」），方便在告警规则里辨认。
3. 选择「类型」，填写对应参数（见下文）。
4. 点击页面底部的保存。
5. 保存后点渠道上的「测试」，确认能收到「通知测试」消息。

::: tip 先保存再测试
「测试」使用的是已保存的配置。改了参数没保存就测试，发出去的还是旧配置。通知总开关关闭或渠道未启用时，「测试」按钮不可用。
:::

已有的渠道默认收起成一行，显示名称、类型、启用开关和「测试」「编辑」按钮。点「编辑」展开表单，修改后点「收起」。

## 各渠道参数

### 企业微信 Webhook

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| Webhook Key | `wecom_webhook.key` | 群机器人 Webhook 地址中 `key=` 后面的部分。 |

在企业微信群里「添加群机器人」，复制 Webhook 地址，只填 `key=` 之后的那一串。

### 钉钉机器人

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| Access Token | `dingtalk.token` | 机器人 Webhook 地址中 `access_token=` 后面的部分。 |
| Secret (加签) | `dingtalk.secret` | 机器人安全设置里「加签」的密钥。 |

网关每次发送都会按加签方式签名，所以在钉钉群里添加自定义机器人时，安全设置请选择「加签」，并把密钥填到 Secret。

### Telegram Bot

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| Bot Token | `telegram_bot.bot_token` | 通过 @BotFather 创建机器人后获得。 |
| Chat ID | `telegram_bot.chat_id` | 接收消息的用户或群组 ID，例如 `12345678`；群组 ID 通常是负数。 |
| API Base | `telegram_bot.api_base` | 默认 `https://api.telegram.org`。使用自建反代时填反代地址。 |
| Proxy URL | `telegram_bot.proxy_url` | 网关访问 Telegram 时使用的代理，例如 `http://127.0.0.1:7890`。 |

网关所在服务器无法直接访问 Telegram 时，填写 Proxy URL 或 API Base 其中之一即可。先给机器人发一条消息，再获取 Chat ID，否则机器人无法主动给你发消息。

### Bark

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| Bark Token | `bark.token` | Bark App 里显示的设备 Key，通过官方服务器 `https://api.day.app` 推送。 |
| Push URL | `bark.push` | 自建 Bark 服务时填写完整的推送地址（包含设备 Key），例如 `https://bark.example.com/你的Key`。 |

两个都填时，会分别向两个地址各推送一次。

### Server 酱

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| SendKey | `serverchan.key` | Server 酱后台获取的 SendKey，Turbo 版以 `SCT` 开头；旧版 Key 也可以使用。 |

## 查看投递情况

每个渠道的标题栏会显示近 7 天的投递统计，例如「近 7 天 12 次送达，1 次失败」。有失败时，卡片里会用红色显示最近一次失败的原因。

失败原因、通知原文和完整的投递历史，都在 <span class="ui-path">安全 › 防护记录</span> 的「告警记录」Tab 里。近 24 小时内有投递失败时，控制台和顶栏铃铛也会提醒。

## 停用与删除

- **停用**：关闭渠道的启用开关并保存，渠道配置保留，告警规则不再向它发送。
- **删除**：点删除后需要确认，删除在点击保存后才生效。引用了这个渠道的告警规则将不再向它发送；如果某条规则只选了这一个渠道，它就收不到任何提醒了，记得到 [告警规则](/guide/security-alerts) 里换一个渠道。

## 常见问题

**测试成功，但告警一直收不到**

检查告警规则页顶部的「安全告警总开关」是否打开、规则是否启用、规则里是否选了这个渠道。再到告警记录里看有没有触发记录：没有记录说明规则没触发，有记录但失败说明是投递问题。

**Telegram 测试超时**

多数是服务器访问不到 `api.telegram.org`，配置 Proxy URL 或 API Base 后重试。

**钉钉返回签名错误**

确认机器人安全设置选的是「加签」，Secret 填的是加签密钥，而不是 Webhook 地址里的 token。
