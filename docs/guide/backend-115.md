# 115 网盘

网关提供三类 115 后端。前两类各访问一个 115 账号；第三类把一个主盘和多个附盘组合起来，把播放分摊到多个账号上。

| 类型 | 界面名称 | 凭据 | 适合 |
|---|---|---|---|
| `115_open` | 115 网盘 Open | 开放平台的 Access Token / Refresh Token | 已开通 115 开放平台的账号 |
| `115_cookie` | 115 网盘 Cookie | 账号 Cookie | 没有开通开放平台的账号 |
| `115_sub` | 115 分流聚合 | 引用一个主盘 + 多个附盘的 Cookie | 播放量大，想分摊单账号的下载限速 |

## 302 还是网关中转

三类后端都有「链路模式」，两个选项：

| 选项 | 配置值 | 播放器从哪里拉流 | 说明 |
|---|---|---|---|
| 302 重定向 | `redirect` | 直接从 115 | 默认值，网关不承担视频流量 |
| 网关中转 (Relay) | `relay` | 从网关 | 网关带上 `Referer: https://115.com` 和播放器的 User-Agent 去 115 取数据再转发，占用网关带宽，流量计入网关统计 |

先用 302。只有播放器直连 115 播不了（比如某些客户端或网页播放器）时，再改成网关中转。

## 115 网盘 Open

在 <span class="ui-path">接入与路由 › 存储后端</span> 新建后端，类型选「115 网盘 Open」。

| 界面字段 | 配置字段 | 默认值 | 说明 |
|---|---|---|---|
| Access Token | `access_token` | — | 开放平台访问令牌 |
| Refresh Token | `refresh_token` | — | 开放平台刷新令牌。访问令牌快过期时网关会自动刷新，并保存新的令牌 |
| Root Folder ID | `root_folder_id` | `0` | 媒体根目录 ID，`0` 为网盘根目录。对象路径相对于这个目录 |
| 链路模式 | `link_mode` | `redirect` | 见上文 |
| 排序字段 | `order_by` | `file_name` | 列目录时的排序字段 |
| 排序方向 | `order_direction` | `asc` | 「升序」或「降序」 |
| 分页大小 | `custom_page_size` | `200` | 每次列目录取多少条，最大 `1000` |
| 302 缓存有效期 (秒) | `link_ttl_seconds` | `1800` | 生成的下载链接按这个时长视为有效；网关中转模式下也是中转令牌的有效期 |
| 路径缓存 | `cache_enabled` | — | 缓存对象路径到文件的对应关系，减少 115 接口调用 |
| 缓存时间 (秒) | `cache_ttl_seconds` | `10800` | 路径缓存的保留时间 |

## 115 网盘 Cookie

类型选「115 网盘 Cookie」。目录、文件信息和下载链接都通过账号 Cookie 获取。

基础配置和 115 网盘 Open 一样，有「Root Folder ID」「链路模式」「排序字段」「排序方向」「分页大小」「302 缓存有效期 (秒)」和「路径缓存」里的「启用缓存」「缓存时间 (秒)」，只是没有 Access Token / Refresh Token。

Cookie 单独保存，不跟着配置一起提交：

1. 先填好其他字段，点页面底部的「保存」，让这个后端存到服务端。
2. 在「Cookie 凭据」分区填入 Cookie，格式类似 `UID=...; CID=...; SEID=...`。
3. 「过期秒数 (元数据)」只用来计算「预计过期时间」，方便你知道什么时候该换 Cookie，不影响实际有效期。
4. 点「保存 Cookie」。「当前状态」变成「已配置」即可。

Cookie 失效后，在同一个后端里换一个新的 Cookie 就行，不需要新建后端。最近一次错误会显示在「最近错误」里。

::: tip
Cookie 等同于账号登录凭据。可以给这个后端设置独立密码，让管理界面默认隐藏它的配置表单；但这只是界面上的遮挡，不是权限隔离，能登录管理界面的人仍有办法拿到配置，所以管理密码一定要设好。详见[后端总览](/guide/backend-configuration#后端独立密码)。

STRM 任务目前支持 115 网盘 Open，不支持 115 网盘 Cookie 和 115 分流聚合。
:::

## 115 分流聚合

115 对单个账号的下载有速度和并发限制。分流聚合把播放请求分到多个账号（附盘）上：

1. 网关先在**主盘**（一个已有的 `115_open` 或 `115_cookie` 后端）里按路径找到文件，拿到文件的 SHA1。
2. 依次尝试附盘：如果附盘里已经有这个文件，直接用；没有就用 SHA1 秒传一份到附盘（不需要真的上传数据）。
3. 从附盘生成下载链接返回给播放器。
4. 所有附盘都失败时，默认回到主盘生成链接。

主盘负责提供媒体目录（对象浏览里看到的是主盘的目录），附盘只负责分担下载。

### 基础策略

| 界面字段 | 配置字段 | 默认值 | 说明 |
|---|---|---|---|
| 主盘后端 (115_open/115_cookie) | `primary_backend_id` | — | 选一个已有的 115 后端作为主盘 |
| 选择策略 | `selection_strategy` | `round_robin` | 「全局轮询 (round_robin)」：所有请求共用一个轮询顺序；「按用户亲和轮询 (user_affinity_rr)」：每个 Emby 用户各自轮询 |
| 用户亲和 | `user_affinity_enabled` | 关闭 | 开启后，用户自己的「用户盘」也加入候选 |
| 用户单盘绑定 | `user_single_drive_only` | 关闭 | 用户有自己的用户盘时，只用这一块盘 |
| 关闭主盘兜底 | `disable_primary_fallback` | 关闭 | 附盘全部失败时直接报错，不再回到主盘 |
| 链路模式 | `link_mode` | `redirect` | 见上文 |
| 302 缓存有效期 (秒) | `link_ttl_seconds` | `1800` | 同 115 网盘 Open |

### 镜像与缓存

| 界面字段 | 配置字段 | 说明 |
|---|---|---|
| 自动镜像目录 | `auto_mirror_dir` | 开启后，秒传到附盘时按主盘的目录结构建立同名目录；关闭则全部放在附盘的 Root Folder 下 |
| 镜像目录前缀 | `mirror_dir_prefix` | 开启自动镜像目录时，在附盘里多套一层目录，例如 `emby_cache` |
| 映射缓存 | `cache_enabled` | 记住文件在每个附盘里的位置，下次不用再查找或秒传 |
| 映射缓存时间 (秒) | `cache_ttl_seconds` | 映射缓存的保留时间，默认 `10800` |

### 附盘池管理

附盘单独保存，不跟着配置一起提交。新建的分流聚合后端要先点页面底部的「保存」，再在「附盘池管理 (动态)」里点「新增附盘」。

| 界面字段 | 说明 |
|---|---|
| 显示名称 | 方便辨认，可选 |
| 盘归属 | 「系统盘」所有用户共用；「用户盘」只给「Owner ID」对应的 Emby 用户用 |
| Owner ID | 盘归属为「用户盘」时填写 Emby 用户 ID |
| Root Folder ID | 附盘里存放秒传文件的目录，默认 `0` |
| 凭据来源 | 「直填 Cookie」在这里直接填 Cookie；「引用 115_cookie 后端凭据」复用某个 115 网盘 Cookie 后端的 Cookie |
| 启用 | 停用的附盘不参与选择 |
| Priority | 数字越小越靠前 |
| Weight | 权重 |

每次请求的候选附盘是：该用户的用户盘（开启「用户亲和」或「用户单盘绑定」时）加上全部启用的系统盘，用户盘在前、系统盘在后，各自按 Priority 从小到大排列；然后按选择策略轮换起点，依次尝试。

::: tip
目前附盘的选择只参考 Priority 和轮询，Weight 不影响选择结果。
:::

### 推荐配置顺序

1. 先建好并验证一个 115 网盘 Open 或 115 网盘 Cookie 后端作为主盘。
2. 新建 115 分流聚合，选择主盘和策略，保存。
3. 在附盘池里逐个添加附盘。
4. 把资源池的主后端指向这个分流聚合后端，见[资源池与故障切换](/guide/routing-and-pool)。
5. 用测试账号播放，在 <span class="ui-path">监控 › 流量分析</span> 的「302 链路」里看每次请求的耗时和结果。

## 常见问题

**附盘或 Cookie 管理提示后端尚未保存**
新建的后端还没存到服务端。先点页面底部的「保存」，再管理 Cookie 或附盘。

**附盘都失败了，播放却还能继续**
这是主盘兜底在起作用。想确认附盘是否正常，看 <span class="ui-path">系统 › 系统日志</span> 里的附盘错误，或者暂时打开「关闭主盘兜底」测试。

**有的文件始终走主盘**
主盘没有返回这个文件的 SHA1 时无法秒传到附盘，会直接用主盘的链接。开启「关闭主盘兜底」后这类文件会播放失败。

**用户亲和看起来没生效**
网关需要识别出 Emby 用户才能按用户选盘。先在 <span class="ui-path">监控 › 用户与媒体</span> 确认播放记录里能看到用户名。

**改成网关中转后流量明显增加**
网关中转会让视频数据经过网关，这是预期行为。
