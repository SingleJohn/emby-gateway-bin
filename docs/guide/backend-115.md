# 115 后端指南

网关提供 `115_open`、`115_cookie` 和 `115_sub` 三类 115 后端。前两类访问单个网盘，`115_sub` 在主盘和动态附盘之间做选择。

## 交付模式

115 系列支持两种链接模式：

| 模式 | 行为 | 观测口径 |
|---|---|---|
| 302 重定向 | 网关返回临时 URL，客户端直连 115 | 网关看不到跳转后的真实字节 |
| Relay | 响应内容经过网关中转 | 网关可观测代理流量，但占用网关带宽 |

除非客户端无法可靠访问直链，否则优先使用 302 模式。

## 115 Open

配置项：

- Access Token、Refresh Token
- Root Folder ID
- 排序字段、升降序和自定义分页大小
- 链接模式、链接有效期
- object key 缓存和缓存时长

默认根目录为 `0`，分页大小默认 `200`，最大 `1000`。Token 属于敏感凭据，不要出现在截图或日志中。

## 115 Cookie

配置项与 115 Open 的目录、排序、分页、链接和缓存设置类似，但访问凭据来自 Cookie 管理接口。

- Cookie 不作为普通明文字段展示。
- Cookie 失效时应更新凭据，不要重复新建后端规避错误。
- 可以给该后端设置独立密码，限制凭据管理范围。

## 115 分流聚合

`115_sub` 需要一个已存在的 `115_open` 或 `115_cookie` 作为主盘后端，再通过附盘池管理动态附盘。

### 选择策略

- **全局轮询** `round_robin`：在可用附盘中轮询。
- **按用户亲和轮询** `user_affinity_rr`：尽量让同一 Emby 用户保持稳定选盘。
- **用户单盘**：用户盘命中后，只使用一个附盘。
- **关闭主盘回退**：附盘全部失败时不再尝试主盘。

用户相关策略依赖可靠的 Emby 用户识别。用户信息暂未补全时，先检查 Source API Key 和「媒体与用户」中的补全状态。

### 镜像目录与缓存

- **自动镜像目录**：为附盘使用统一镜像目录结构。
- **镜像目录前缀**：默认可使用 `emby_cache`，应与实际目录规划一致。
- **缓存**：减少目录和 object key 查询，但配置变化后要考虑缓存时效。

### 附盘凭据

附盘支持两种方式：

- 引用一个现有 `115_cookie` 后端作为凭据来源。
- 在附盘记录中使用独立 Cookie。

每个附盘还可配置名称、所有者类型、所有者 ID、根目录、权重、优先级和启用状态。这里的权重属于 `115_sub` 附盘选择，不是资源池权重；普通资源池仍只有固定主备关系。

## 推荐配置顺序

1. 创建并验证 `115_open` 或 `115_cookie` 主盘。
2. 新建 `115_sub`，选择主盘和分流策略。
3. 先保存 `115_sub` 后端。
4. 打开附盘池管理，逐个添加凭据和根目录。
5. 创建资源池和路由，用测试用户发起播放。
6. 在「流量分析 → 302 链路」确认实际选盘和交付模式。

## 常见问题

- **附盘管理不可用**：`115_sub` 尚未保存到服务端。
- **用户亲和不稳定**：用户 ID 没有被正确识别或请求来自不同 Source。
- **附盘失败后没有回主盘**：检查是否开启“关闭主盘回退”。
- **Relay 流量明显增加**：Relay 会让媒体内容经过网关，这是预期行为。
- **根目录能浏览但播放找不到文件**：检查路径映射、镜像目录前缀和附盘 Root Folder ID 是否使用同一 object key 口径。
