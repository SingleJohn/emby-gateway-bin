# 控制台与关注中心

登录管理界面后先看到的就是控制台。这一页说明控制台各区块的含义，顶栏铃铛（关注中心）会提醒哪些事情，以及配置健康检查查的是什么。日常巡检看这一页就够了，有问题再按提示点进对应页面。

## 控制台

位置：<span class="ui-path">首页 › 控制台</span>。页面默认每 10 秒自动刷新，右上角可以关掉「自动刷新」，或者手动点刷新按钮。旁边的下拉框可以只看某一个 Emby 源的数据。

### 顶部概况

问候语下面有一句状态结论：没有待处理事项时显示「系统运行平稳，暂无需要处理的事项」，否则显示「有 N 项需要你处理」。再往下是三枚小标签：

- **Emby 源 N/M 在线**：已启用的 Emby 源中，上游能连通的数量。
- **并发限制状态**：「并发限制生效中」「仅统计并发」或「未启用并发限制」，对应 [播放限制](/guide/security) 的设置。
- **授权剩余 N 天**：授权有效时显示。

### 核心指标

四张指标卡，点击可以跳到对应的详细页面：

| 指标 | 含义 | 点击后去往 |
|---|---|---|
| 今日请求 | 今天经过网关的请求数，副标题是昨天全天的数字 | 流量分析 |
| 今日下行流量 | 今天由网关发出的流量。302 之后客户端直接从存储下载的流量不计入 | 流量分析 |
| 活跃播放 | 当前正在播放的路数和在看的用户数 | 实时播放 |
| 直链命中率 | 近 30 天 302 跳转占全部请求的比例，副标题是平均延迟 | 流量分析的「302 链路」 |

::: tip 直链命中率是最值得盯的数字
它越高，说明越多播放请求被网关直接分流到了存储；如果突然下降，通常是路由规则、路径映射或后端出了问题，请求都回退给 Emby 代理了。
:::

### 需要关注

和顶栏铃铛显示同一份清单，按严重程度排序，每一项都带一个处理按钮。右上角的「N 项待处理」只统计需要动手处理的项（错误和警告），不含提示类信息。具体有哪些事项见下文 [关注中心](#关注中心)。

### 服务状态

列出管理 API 和每个已启用的 Emby 源：

- 绿色并显示毫秒数：上游 Emby 可以连通，数字是本次检测的延迟。
- 「不可达」：网关连不上这个源的上游 Emby。
- 「未检测」：网关还没对它做过检测。

网关每 30 秒自动检测一次上游，单次超时 5 秒。每一行右侧的刷新按钮可以立即重测一次。点卡片右上角的「管理 →」进入 Emby 源页面。

### 趋势图

- **近 30 天请求量与流量**：左轴是请求数，右轴是下行流量（GiB）。
- **状态构成**：近 30 天各类响应状态码的占比。
- **近 24 小时分时请求**：按小时聚合，按状态码堆叠，适合看高峰时段和错误突增。
- **常用入口**：实时播放、流量分析、防护记录、Emby 源、存储后端、STRM 任务的快捷入口。

## 关注中心

顶栏的铃铛就是关注中心。进入管理界面时会拉取一次，之后页面处于可见状态时每分钟刷新一次。铃铛上的数字和控制台「需要关注」一致，只统计错误和警告。侧栏菜单上也会出现小角标，告诉你问题出在哪个页面，比如上游不可达时「Emby 源」旁边会出现红色计数。

关注中心会汇总下面这些事项：

| 事项 | 级别 | 什么时候出现 | 点击后去往 |
|---|---|---|---|
| 授权状态异常 | 错误；宽限期为警告 | 授权未激活、已过期、无效、系统时间异常、授权服务未配置，或处于宽限期 | 授权 |
| 授权即将到期 | 警告；3 天内为错误 | 授权有效，但距到期不足 14 天 | 授权 |
| Emby 源上游不可达 | 错误 | 某个已启用的源连不上上游 Emby | Emby 源（自动选中该源） |
| 配置异常 | 警告 | 配置健康检查发现问题，见下文 | 有路由问题时去 Emby 源，否则去使用说明 |
| 用户正被自动封禁 | 警告 | 有用户因多 IP 等自动防护规则正处于封禁期 | 防护记录 › 当前封禁 |
| 告警投递失败 | 警告 | 近 24 小时有告警没能送达某个通知渠道 | 防护记录 › 告警记录（只看失败） |
| STRM 任务运行失败 | 警告 | 某个任务最近一次运行有错误 | STRM 任务 › 运行记录 |
| 来源因登录失败被锁定 | 提示 | 有 IP 因登录失败防护被锁定 | 防护记录 › 登录锁定 |
| 近 24 小时拦截请求 | 提示 | 近 24 小时安全规则拦截过请求，会单独列出登录失败防护的次数 | 防护记录 |

每个数据来源各自独立加载，某一项取数失败只会让这一项暂时不显示，不影响其他项。

## 配置健康检查

网关会对当前配置做一次静态检查。结果会出现在关注中心的「N 项配置异常」里，也会显示在「使用说明」页顶部。检查只针对**已启用**的 Emby 源，分三类：

1. **监听端口冲突**：两个及以上已启用的 Emby 源使用了同一个 `listen_port`。只有一个能真正监听，其他源会不可用。
2. **引用失效**：已启用的路由规则引用了不存在的路径映射（Path Rule Set）或资源池，或者资源池里的主后端、备后端已经被删除。这样的规则命中后无法生成直链。
3. **被遮蔽的路由规则**：如果一条规则匹配全部路径（没有任何匹配条件，或者前缀是 `/`），又排在其他规则前面，它后面的规则永远不会被匹配到。处理方法是把这条兜底规则的优先级数字调大，让它排到最后。详见 [路由规则](/guide/emby-sources#路由规则)。

::: tip
健康检查只看配置之间的引用关系，不会去连接后端。后端能不能用，以存储后端页面的连接测试和流量分析里的实际结果为准。
:::

## 使用说明页

位置：<span class="ui-path">系统 › 使用说明</span>。这一页把当前配置画成一张关系图，方便理解一次播放请求会怎么走：

- **配置健康**：顶部显示「配置健康」或「N 项配置异常」，并列出端口冲突和失效引用的具体条目。
- **统计卡**：Emby 源、路径映射集、资源池、存储后端的数量，点击可以直接进入对应的配置页面。
- **配置拓扑**：每个已启用的 Emby 源下有哪些路由规则（按优先级排序），各自引用了哪个路径映射和资源池。
- **中间件链路**：请求进入网关后依次经过真实 IP 解析、安全防护、请求日志，最后到路由或反向代理。
- **直链播放流程**：普通 Emby 播放请求分六步处理，依次是捕获请求、向 Emby 查询媒体的真实路径、路由匹配、路径转换、生成直链、302 跳转。任何一步失败都会回退为反向代理，交给 Emby 处理。
- **直接访问流程**：`/stream/...` 路径不经过 Emby API，直接把网址中的路径当作媒体路径，做路由匹配和路径转换后跳转。
