# 介绍与工作原理

Feiyue Emby Gateway（飞跃 Emby 网关）部署在 Emby 前面。播放器连接网关的端口，网关把视频流请求按媒体路径分流到对象存储、网盘或本地磁盘，用 302 直链交给播放器；其余请求照常转发给 Emby。

第一次接触本产品，建议先读完这一页，再按 [快速开始](/guide/quick-start) 部署。

## 解决什么问题

- **服务器带宽不够**：媒体放在 S3、CDN 或网盘里，但播放时视频仍要经过 Emby 服务器中转。网关返回直链后，视频数据由播放器直接从存储下载，服务器只处理很小的请求。
- **存储分散**：电影在对象存储、剧集在网盘、新片在本地盘。网关按路径把它们分别交给对应的存储，Emby 侧不需要改动。
- **单一存储不稳定**：同一份媒体放在两个地方时，可以配成主备，主用后端生成直链失败时自动换备用。
- **账号共享和异常访问**：登录失败锁定、多 IP 封禁、并发播放限制、访问规则和告警通知，都在网关层完成。
- **看不清播放情况**：实时会话、请求日志、302 链路耗时、用户播放记录和访问来源，都有现成的页面。

## 适用场景

- 一个或多个 Emby 服务器，媒体放在对象存储或网盘里，希望播放走直链。
- 同时使用多种存储，需要按目录分流。
- 对外开放 Emby 给亲友或用户使用，需要防护和并发控制。
- 想通过统计和告警及时发现异常，而不是等用户反馈。

## 工作原理

<FlowDiagram />

播放器发来的请求分两类处理：

| 请求 | 例子 | 网关怎么处理 |
|---|---|---|
| 媒体流请求 | `/Videos/{id}/stream`、`/Videos/{id}/original`、`/Audio/{id}/universal`、`/Items/{id}/Download` | 尝试生成直链，返回 `302` |
| 其他请求 | 登录、媒体库浏览、海报图片、播放信息、播放进度上报、WebSocket | 原样代理给 Emby |

媒体流请求在网关里依次经过：

1. **查询真实路径**：网关用 Emby 源里配置的 API Key 向 Emby 查询这个媒体文件的真实路径。
2. **路由规则**：按该 Emby 源下路由规则的优先级数字从小到大依次匹配，第一条命中的规则生效，后面的不再看。
3. **路径映射**：用命中规则指定的规则集，把 Emby 里的路径（如 `/mnt/media/movies/阿凡达.mkv`）换成存储里的路径（如 `/movies/阿凡达.mkv`）。
4. **资源池**：先用主用后端生成直链，失败再试备用后端。
5. **交付**：拿到直链后返回 `302`，播放器跳转过去直接拉流；后端选择了中转（Relay）时，数据经网关转发。

### 什么时候回退代理

下面这些情况网关不返回 302，而是把请求照常交给 Emby，播放不会因此中断，只是视频流量回到了 Emby 服务器：

- Emby 源没有填写 API Key，或向 Emby 查询真实路径失败；
- 没有命中任何启用的路由规则；
- 命中的规则开启了「强制映射」（新增规则的默认值），但规则集里没有一条映射能匹配；
- 主用和备用后端都没能生成直链。

例外是资源池里用了「外部解析服务」后端：命中这类路由后由解析服务负责交付，失败时直接报错，提示播放器重新发起播放，不会回退。

::: tip 怎么知道走的是哪条路
Emby 源页面的「匹配测试」可以在保存前模拟一个路径会命中哪条规则；播放后在 <span class="ui-path">监控 › 流量分析</span> 的「302 链路」里能看到实际的跳转情况。
:::

### 302 直链与中转

| 方式 | 视频数据怎么走 | 适合 |
|---|---|---|
| 302 直链 | 播放器 → 存储，不经过网关 | 播放器能直接访问存储（公网对象存储、CDN、网盘直链） |
| 中转（Relay） | 播放器 → 网关 → 存储 | 存储只对网关可达，或直链对播放器有限制 |

中转只在部分后端上可选，例如 115 系列和外部解析服务的「中转」模式；本地存储则由网关直接提供文件。中转会占用网关服务器的带宽，详见 [核心概念](/guide/concepts#中转)。

### 控制面与数据面

| | 职责 | 端口 |
|---|---|---|
| 数据面 | 接收播放器请求，代理 Emby，生成直链或中转 | 每个 Emby 源各自的监听端口 |
| 控制面 | 管理界面、配置、统计查询、告警与通知 | 管理端口（默认 `18888`） |

播放器只需要访问 Emby 源的端口。管理端口只给管理员使用，不应暴露到公网，见 [部署与升级](/guide/deployment#安全基线)。

### 配置即时生效

配置保存在数据库里（SQLite 或 PostgreSQL）。在管理界面保存后立即生效，不需要重启，包括新增或停用 Emby 源、修改 Emby 源的监听端口。只有管理端自身的「Admin Host」和「Admin Port」要重启网关后才会生效。

::: tip
网关会自动开始监听新端口，但防火墙、云服务器安全组和 Docker 端口映射需要你自己放行。
:::

### 网关不做什么

- 不存储媒体文件，也不改动 Emby 的媒体库。
- 不替代 Emby 的用户体系：用户、权限、媒体库仍在 Emby 里管理。
- 返回 302 之后，播放器和存储之间的传输不经过网关，网关看不到实际下载了多少字节。

## 功能一览

管理界面按任务分为六组，每组对应文档里的一个章节。

### 首页

- **控制台**：今日请求、流量、302 命中率、活跃播放等指标和趋势图；「需要关注」汇总授权、Emby 上游、配置和安全方面待处理的事。见 [控制台与关注中心](/guide/dashboard)。

### 监控

- **实时播放**：当前播放会话与并发，可手动释放会话计数。
- **流量分析**：请求趋势、请求日志、302 链路各阶段耗时。
- **用户与媒体**：媒体请求、使用统计、播放记录。
- **访问来源**：来源 IP 的地区和运营商分布，可从 Top IP 直接查看它的请求或拦截记录。

见 [播放与流量监控](/ops/observability)。

### 安全

- **防护记录**：拦截事件、登录锁定、当前封禁、封禁历史、告警记录，锁定和封禁可以手动解除。
- **防护策略**：访问规则、登录失败防护、多 IP 封禁、请求频率、播放限制、真实 IP。
- **告警规则**：按用户、IP 等维度检测异常并发送通知。

见 [防护记录](/guide/security-records)、[防护策略](/guide/security)、[告警规则与告警记录](/guide/security-alerts)。

### 接入与路由

- **Emby 源**：网关对外的 Emby 入口，以及按路径分流的路由规则，内置匹配测试。
- **路径映射**：Emby 路径到存储路径的转换规则，内置映射测试。
- **资源池**：一个主用后端加一个可选的备用后端。
- **存储后端**：S3 对象存储、阿里云 CDN、123 网盘、115 网盘、Google Drive、本地存储、Local Agent、外部解析服务。

见 [Emby 源与路由规则](/guide/emby-sources)、[路径映射](/guide/path-mapping)、[资源池与故障切换](/guide/routing-and-pool)、[后端总览](/guide/backend-configuration)。

### 媒体库工具

- **对象浏览**：直接浏览存储后端里的目录和文件。
- **STRM 任务**：扫描存储，批量生成 `.strm` 文件给 Emby 入库。
- **123 转码**：123 网盘视频按需转码（仅管理员可见）。

见 [对象浏览](/guide/file-browser)、[STRM 任务](/guide/strm-guide)、[123 转码](/guide/pan123-transcode)。

### 系统

- **系统设置**：管理端访问、日志与统计保留、缓存、IP 归属解析、数据库维护、GDrive Worker。
- **通知渠道**：企业微信 Webhook、钉钉机器人、Telegram Bot、Bark、Server 酱。
- **系统日志**：网关运行日志，支持组合筛选。
- **授权**：激活与剩余天数。
- **使用说明**：配置健康检查与请求流程图解。

见 [系统设置](/guide/system-settings)、[通知渠道](/guide/notification)、[系统日志](/guide/system-logs)、[授权](/guide/license)。
