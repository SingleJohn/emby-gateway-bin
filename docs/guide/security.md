# 防护策略

防护策略在请求到达 Emby 之前生效，用来挡住爬虫和异常客户端、限制账号共享、防止暴力破解登录。这里只负责「怎么防」；被拦截、被封禁、被锁定的记录在 [防护记录](/guide/security-records) 里看。

入口：<span class="ui-path">安全 › 防护策略</span>

## 总开关与生效条件

页面顶部的「安全防护总开关」统一控制访问规则、自动防护、并发限制的强制执行和 Infuse 拉流限制。关闭时这些设置都可以照常编辑和保存，只是不执行。

有几项不受总开关影响：

- 「统计播放会话」：按自己的开关记录活跃播放，供控制台和 [实时播放](/ops/observability) 使用；
- 「匿名播放兼容」：按自己的开关生效；
- 账号禁用和媒体播放权限始终校验。

::: tip 需要授权
安全防护需要授权中包含安全功能；没有该功能时，即使打开总开关也不会执行。详见 [授权](/guide/license)。
:::

所有修改都要点底部的保存才会生效，保存后立即应用，不需要重启。

## 访问规则

访问规则按客户端 IP、请求路径、User-Agent、请求方法等条件匹配请求，然后放行、拦截或限流。

- 规则**按列表顺序**匹配，第一条命中的规则决定结果，后面的不再看。用上移、下移调整顺序。
- 按 IP 等条件的规则在身份验证前执行；限流维度是「用户 ID」或「Source + 用户 ID」的规则，在确认 Emby 用户身份之后执行。
- 「使用模板」可以从内置模板快速新建常用规则，再按需修改。
- 列表上方的搜索框可以按规则名称或匹配条件查找。

### 匹配条件

点「新建规则」或编辑已有规则，在「匹配条件」里设置：

| 条件 | 配置键 | 说明 |
| --- | --- | --- |
| 请求范围 | `match.request_scope` | 「全部请求」「普通 API」「媒体请求」，只对这一类请求生效。 |
| 适用 Source | `match.source_id` | 只对选中的 Emby 源生效，留空表示全部。 |
| 客户端 IP (CIDR) | `match.ip_cidr` | 例如 `192.168.1.0/24`。 |
| 请求路径 | `match.path_prefix` / `match.path_regex` | 前缀匹配或正则匹配，例如 `/Videos/`、`^/Items/\d+$`。 |
| User-Agent | `match.ua_contains` / `match.ua_regex` | 包含关键词（不区分大小写）或正则，例如 `python-requests`。 |
| 请求方法 | `match.method` | GET、POST、HEAD，留空匹配所有。 |

同一类条件内部是「或」（多个路径前缀命中任一即可），不同类条件之间是「且」（同时配置了 IP 和路径，两者都要命中）。一个条件都不填，规则匹配全部请求。

### 执行动作

| 策略类型 | 配置值 | 行为 |
| --- | --- | --- |
| 放行 (Allow) | `allow` | 直接放行，不再看后面的规则。 |
| 拦截 (Deny) | `deny` | 返回「返回状态码」（默认 403）和「错误信息」（默认 `blocked`）。 |
| 限流 (Rate Limit) | `rate_limit` | 按「限流维度」分组，每组按「速率 (RPS)」和「突发 (Burst)」放行；超出时返回限流状态码（默认 429）。 |

限流维度（`action.rate_limit.key`）：

| 选项 | 配置值 | 计数方式 |
| --- | --- | --- |
| 仅 IP | `ip` | 同一个 IP 共享一个限流桶 |
| IP + 路径 | `ip_path` | 同一 IP 的不同路径分开计数 |
| IP + UA | `ip_ua` | 同一 IP 的不同客户端分开计数 |
| Source + IP | `source_ip` | 不同 Emby 源下的同一 IP 分开计数 |
| Source + IP + 路径 | `source_ip_path` | 按 Emby 源、IP、路径分桶，最细 |
| Source + IP + UA | `source_ip_ua` | 按 Emby 源、IP、客户端分桶 |
| 用户 ID | `user_id` | 按已验证的 Emby 用户分桶 |
| Source + 用户 ID | `source_user` | 按 Emby 源 + 已验证用户分桶 |

::: warning 限流规则命中后也会停止匹配
请求命中一条限流规则且没有超限时，结果是放行，后面的规则不会再执行。想先拦截某些请求，再对其余请求限流，要把拦截规则排在限流规则前面。
:::

## 自动防护

自动防护按用户行为自动处置，不需要逐条写规则。

### 按请求类型限流

每个 Emby 源内，按已验证用户分别计数，同一用户的多台设备共用额度。请求按用途分成六类，各自独立开关和设置额度：

| 分类 | 统计的请求 |
| --- | --- |
| 普通 API 请求防护 | 浏览、搜索、详情、封面等。登录和公共接口由登录失败防护或访问规则处理。 |
| 播放准备与地址申请防护 | PlaybackInfo 和首次申请播放地址。同设备、同媒体的短时重复准备合并计数，另有一个包含重复请求的原始额度。 |
| 媒体传输防护 | Range、HLS 清单和分段、字幕、中转，每个请求计一次。 |
| 播放上报防护 | Start、Progress、Stopped 播放上报，正常心跳不占其他额度。 |
| HEAD 与探测防护 | HEAD 和携带用户凭证的预检请求。 |
| 用户总请求兜底 | 合计该用户的所有请求，不做去重。额度设得过低可能影响正常播放的分段和心跳。 |

每一类有三层处置：

1. **请求限流**：按最近 60 秒统计，超过「请求额度 / 60 秒」时返回 429，暂时拒绝这一类请求。
2. **持续异常封禁**：超限次数达到「纳入持续异常的超限次数」后进入异常观察，连续异常窗口数达到「封禁所需的连续异常窗口数」才临时封禁该用户。偶尔超限一次不会被封。
3. **严重洪泛直接封禁（可选）**：按原始请求总数判断，达到「直接封禁的原始请求总数 / 60 秒」立即封禁。填 0 表示不启用。

一旦触发临时封禁，该用户的所有请求都会被拒绝，直到到期或被手动解除。封禁时长、适用 Source 和例外用户与下面的「多 IP 防护与公共参数」共用。

### 多 IP 防护与公共参数

打开「启用用户多 IP 临时封禁」后，网关在每个 Emby 源下按用户统计「多 IP 统计范围」内的请求来自多少个不同 IP。最近一个「统计窗口（秒）」里不同 IP 数超过「允许的最大 IP 数」时，立即临时封禁该用户。

| 字段 | 配置键 | 默认值 |
| --- | --- | --- |
| 多 IP 统计范围 | `user_ip_limit.ip_request_scope` | 媒体请求（可选全部请求、普通 API、媒体请求） |
| 统计窗口（秒） | `user_ip_limit.window_seconds` | 600 |
| 允许的最大 IP 数 | `user_ip_limit.max_ips` | 3 |
| 封禁时长（秒） | `user_ip_limit.ban_seconds` | 1800 |
| 适用 Source | `user_ip_limit.source_ids` | 留空表示全部（各源分别统计） |

- 上限为 3 时，第 4 个不同 IP 出现即触发封禁；同一个 IP 重复访问只刷新出现时间。
- 封禁期间重试不会延长封禁时间；到期或手动解封后重新统计。
- 网关重启后 IP 重新统计，未到期的封禁会恢复。修改这些参数也会重新统计，已有封禁保留原到期时间。

### 自动防护例外用户

「添加例外」后选择 Emby 源并填写用户 ID，该用户在这个源内不再触发多 IP 和高频自动处罚。账号禁用、媒体权限和访问规则仍然执行；例外之前已经生效的封禁需要另外在 [防护记录](/guide/security-records) 里解除。

### 登录失败防护

多次登录失败后按 IP 临时封禁，缓解暴力破解。

| 字段 | 配置键 | 默认值 |
| --- | --- | --- |
| 最大失败次数 | `login_failure_protection.max_fails` | 5 |
| 作用范围 | `login_failure_protection.scope` | 「按 Source + IP」（`source_ip`）；也可选「全局 IP」（`ip`） |
| 统计窗口 (秒) | `login_failure_protection.window_seconds` | 300 |
| 封禁时长 (秒) | `login_failure_protection.ban_seconds` | 3600 |
| 生效 Source | `login_failure_protection.source_ids` | 留空表示全部 |
| 登录接口路径 | `login_failure_protection.paths` | `/Users/AuthenticateByName` |
| 失败状态码 | `login_failure_protection.status_codes` | `401` |

「按 Source + IP」时，同一个 IP 在不同 Emby 源上的失败分开计数；「全局 IP」时合并计数。被锁定的 IP 可以在防护记录的「登录锁定」Tab 里手动解锁。

### 接口防护

- **禁用下载接口**：拦截 Direct File 直接下载（`/Items/.../download`、`/Sync` 文件），返回 403。
- **禁用同步 / 离线接口**：拦截 `/Sync` 同步与离线下载相关接口，返回 403。

## 播放限制

### 并发播放限制

| 字段 | 说明 |
| --- | --- |
| 统计播放会话 | 记录活跃播放，供控制台和实时播放页统计，不拦截。不受安全总开关影响。 |
| 强制并发限制 | 超出限额时拒绝播放，按 Emby 源 + 用户分别计数。 |
| 会话空闲超时 (秒) | 会话多久没有心跳就自动释放，默认 600。 |
| 生效 Source（限制） | 留空表示全部。 |
| 每用户默认限额 (0=不限) | 每个用户同时播放的上限。 |
| 拒绝状态码 | 默认 429。 |
| 拒绝提示文案 | 超限时返回给客户端的提示，例如「已达到最大同时播放数量」。 |
| 按用户独立限额 (UserId) | 给个别用户单独设置上限，覆盖默认限额。 |

302 直链播放时视频流不经过 Emby，所以并发以网关自己统计的播放会话为准。

### Infuse 重复拉流限制

开启「抑制 Infuse 整文件重拉」后，Infuse 把整个文件拉完一遍后，后续请求只转发「探测切片 (MiB)」大小（默认 4 MiB）的数据，避免反复整文件下载。只对**走网关中转（非 302）**的 Infuse 播放生效，302 直链不受影响。

### 匿名播放兼容

部分播放器内核（例如 Filebar 内置的 VLC）请求视频时不携带任何 Token。打开「允许无凭证的媒体流」后，完全不带凭证的视频、音频、字幕流请求会被放行；带了无效 Token 的请求仍会被拒绝。

::: danger 开启前先了解影响
这类请求没有用户身份：媒体权限、用户禁用、多 IP 封禁、请求限流和并发限制都对它不生效，知道条目 ID 就能拿到直链。按 IP 的访问规则仍然有效。PlaybackInfo、下载、HLS 和按真实路径的直链入口始终需要用户凭证。只在确实有这类播放器时，按 Emby 源开启。
:::

上游是 FYMS 时，字幕由网关反代到 FYMS，需要同时在 FYMS 里开启「匿名媒体兼容模式」。

## 真实 IP

网关部署在反向代理或 CDN 后面时，要正确识别客户端的真实 IP，否则所有请求看起来都来自代理，IP 规则、多 IP 封禁和登录失败防护都会失准。

| 字段 | 配置键 | 说明 |
| --- | --- | --- |
| Header | `real_ip.header` | 读取真实 IP 的请求头，例如 `X-Forwarded-For`、`CF-Connecting-IP`。 |
| 信任所有代理 (Trust Any) | `real_ip.trust_any_proxy` | 信任任何来源发来的请求头。任何人都能伪造 IP，不推荐开启。 |
| 可信代理白名单 (CIDR) | `real_ip.trusted_proxies` | 只信任来自这些地址的请求头，每行一个，例如 `127.0.0.1/32`。 |

白名单为空时直接使用连接的来源地址。`X-Forwarded-For` 会从右向左回溯，取第一个不在白名单里的地址作为客户端 IP。

## 推荐做法

1. 先配好「真实 IP」，在 [访问来源](/ops/observability) 里确认看到的是真实客户端地址。
2. 打开「统计播放会话」和「登录失败防护」，这两项几乎没有误伤。
3. 自动防护先只开启「请求限流」，观察 [防护记录](/guide/security-records) 一段时间，确认没有误伤后再开启封禁。
4. 家人朋友多设备使用的账号，加入「自动防护例外用户」。
5. 配合 [告警规则](/guide/security-alerts)，封禁和异常第一时间推送到手机。
